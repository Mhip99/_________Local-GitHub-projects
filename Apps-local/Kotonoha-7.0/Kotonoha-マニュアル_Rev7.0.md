## 1. 準備編（セットアップ）

別マシンでの導入手順です（リポジトリ同梱の `README.md` と同一内容）。本ツールはローカル専用（`127.0.0.1`）で、機密は原則として外部へ送信しません。

### 1.1 必要環境
- Windows ＋ **Python 3.x**（`python` が PATH に通っていること）。
- （任意）**LanguageTool**：英語のリアルタイム文法チェックを使う場合（`_install-LanguageTool.bat` で自動導入）。
- （任意）**pandoc**：本マニュアル docx を再生成する場合のみ。

### 1.2 入手
- リポジトリを取得（clone / fetch）：`github.com/Mhip99/_________Local-GitHub-projects`。本体＝`Apps-local\Kotonoha-7.0\`。

### 1.3 パス設定（マシンごと・任意）
- 索引キャッシュや LanguageTool の場所を既定から変える場合、`_kotonoha-paths.bat.sample` を **`_kotonoha-paths.bat`** にコピーし、`set "CACHE=…"`（索引キャッシュ）/ `set "LTDIR=…"`（LanguageTool）を設定（**Git管理外**＝マシン固有）。
- 既定：索引＝`Kotonoha-7.0\_Index`（初回自動作成）、LanguageTool＝`%LOCALAPPDATA%\Kotonoha-LT`。

### 1.4 TM データの配置（重要）
- TM（XTM の TMX 等・数百MB）は**リポジトリに含まれません**。各自で TMX を配置し、プロジェクト作成時にそのパスを指定します。**TM が無いと解析・TMタブ・Concordance は動きません**（UI 起動は可能）。

### 1.5 起動
- **`起動_Kotonoha-ハブ.bat`** をダブルクリック → ブラウザで `http://127.0.0.1:8765/`。黒いコンソール窓を閉じると停止（LanguageTool も同時停止）。
- 推奨ブラウザ：**Edge**、または拡張（Dark Reader 等）を `127.0.0.1` で無効化した Chrome。

### 1.6 プロジェクト作成・実行
- 「プロジェクト」タブ（またはランチャー `[C]`）でソース・メインTM・Product/サブTM を指定して作成 → 実行。生成記事（TEPタブ）でレビュー・確定 → 「TEP完了」／「出力」（詳細は §5・§5a/5b/5c）。

### 1.7 （任意）英語リアルタイム文法（LanguageTool）
- **`_install-LanguageTool.bat`** を一度実行（ポータブル JRE ＋ LanguageTool を `%LOCALAPPDATA%\Kotonoha-LT` へ自動導入／約290MB）。以後、起動bat が自動起動。操作行「スペル・文法チェック」ON で英語はリアルタイム、日本語は Claude 半自動点検（外部送信なし）。詳細は §11.25。

### 1.8 （任意）マニュアル docx 再生成
- pandoc 導入後 `_build-manual-docx.bat`。原本は `Kotonoha-マニュアル_Rev7.0.md`。

> セキュリティ・注意：ローカル専用・`/api/*` トークン必須・Host 検証・未信頼データは常に `esc()`。詳細は **§12 セキュリティ**。機密（Domo）コンテンツを含むためリポジトリ共有は社内ルールの範囲で。

**一括の作業順**： **[C]（または [5] 初回のみ → [C]）→ Claude で `combined.mt-todo.json` を翻訳 → [4] → ブラウザで TEP＋確定 → XLIFF書き出し → [7] 書き戻し**。

### パスの記憶（前回値を既定表示）
- 各メニューの入力は **前回値を既定表示**。Enter で据置、変更する時だけ入力。値は `_paths.cfg`（`KEY=VALUE`）に自動保存。
- Product TMX を使わない／Project TM を Master のみにする場合は **`-`（ハイフン）** で空にできます。[8] で一覧確認と一括変更。

### 入力エラー時の挙動（再入力 / キャンセル）
- 見つからないパスや空の必須項目は `※ …が見つかりません` → **`再入力(R) / キャンセル(C)`**。**C は一つ前の入力に戻る**（最初の入力での C は中止してメニューへ）。

> ⚠ `.bat` は **CRLF 改行**で保存してください（LF のみだと Windows の cmd が正しく解釈できません）。

## 5a. プロジェクト管理（作成 [C] / 一覧 [P]）

作業対象をまとめた「プロジェクト」を作成・管理し、いつでも作業を再開できます。台帳は `_projects.json`、一覧は `_projects.html`。

### [C] プロジェクト作成＋実行（ウィザード）
次の順で入力します（各ステップで現在の内容を再表示。見つからないパスは `再入力(R) / キャンセル(C=一つ前)`）。
1. **プロジェクト名**
2. **ソースの追加**：`F=ファイル追加` ／ `D=フォルダー追加（階層維持）` ／ `U=直前を取消` ／ `X=次へ`。単一／複数まぜて何件でも。
3. **メイン TM**（1つ・マッチ用）：`A=既存を指定` ／ `N=新規作成（空 TMX）`。
4. **Product TM**（任意・用語集ヒント）：`A=既存を指定` ／ `S=使わない`。
5. **サブ TM**（複数可・マッチ用）：`A=追加` ／ `N=新規作成` ／ `U=取消` ／ `X=次へ`。
6. **追加情報（任意）**：出力先フォルダー・担当者・期日・メモ。
7. 内容を一覧表示して**定義を保存**。続けて「今すぐ 解析＋Pre-translation を実行しますか？」で **Y＝実行**（成果物を台帳に登録）。

### [P] 過去のプロジェクト（ダッシュボード／コンソール操作）
`[P]` でブラウザの別タブに一覧ダッシュボードを開き、コンソールで番号を選んで操作します。
- **記事行の「開く」**：成果物 HTML を別タブで開き、作業再開。
- **定義行**：`G`＝保存した定義を解析＋Pre-translation 実行／`X`＝**元の形式で翻訳版を出力**（→ §5c）。
- `S`＝状態（作業中／レビュー中／完了）、`M`＝メモ、`E`＝期日、`D`＝削除（ファイル保持／削除を選択）、`N`＝新規作成、`R`＝再表示。
- ダッシュボード表：検索／状態フィルタ／列幅・表示・並べ替え・固定・既定復帰（ブラウザ保存）。

> ブラウザ上での操作（作成・実行・編集・各ツール）は **[D] サーバーモード**（§5b）で行えます。

## 5b. サーバーモード [D]（全機能をブラウザGUIで）

`[D]` で `projects.py serve` を起動します。**127.0.0.1 限定・ランダムトークン認証**（`X-KT-Token`）付きのローカルサーバーで、ブラウザが自動で開きます。終了はコンソールで **Ctrl+C**。

ブラウザのダッシュボード（サーバーモード）でできること：

- **＋ 新規作成**：モーダルで名前・ソース（複数）・メイン/Product/サブ TM を指定して作成（**作成のみ** / **作成して実行**）。
- **各定義行**：「**実行**」（解析＋Pre-translation・ワンクリック）／「**出力**」（元形式で翻訳版・§5c）。
- **各行の「編集」**：状態（セレクト）・メモ・期日の変更、**削除**（2段階確認）。
- **ツールバー「ツール ▾」**：
  - **MTをHTMLに反映**（単一＝HTML＋mt-done／一括＝combined）。
  - **索引キャッシュを事前作成**（University＋Product を指定。数分かかる場合あり）。
  - **TEP 結果を TM に書き戻す**：まず **dry-run** でプレビュー → 確認 → 本実行。**本実行の直前に書込先 TMX を日付きバックアップ**（`<名前>.bak_YYYYMMDD-HHMMSS.tmx`）。
  - **UI Glossary を作成**（§8b）。完了後「出力フォルダを開く」。
- **ファイル指定**は **Windows 標準の「ファイルを開く／フォルダー参照」ダイアログ**（前面表示）。tkinter が使えない環境では、サーバー内蔵のファイルブラウザに自動フォールバック。

> 重い処理（索引ビルド等）は**同期実行**です。「実行中…」の間は**タブを閉じない**でください。処理中もサーバーは他の操作を受け付けます。
>
> 静的な `_projects.html` を直接（`file://`）開いた場合は、作成・実行・編集・各ツールは使えません（「実行」はコマンドのコピーのみ）。全操作には **[D] サーバーモード**を使ってください。

## 5c. 元の形式で翻訳版を出力（JSON/DOCX/XLSX ＋ 保存先選択）

**元のファイル形式のまま翻訳版**を出力します。ダッシュボードの「**出力**」ボタン、CLI は `export`。

- **対応形式**：`.json`（Domoアプリ）・`.docx`・`.xlsx`・`.txt`（`doc_io` のレジストリ）。PDF・旧バイナリは対象外。
- **JSON の出力**は、TM の再照合ではなく**記事の訳文（Pre-translation の結果＋MT＋編集）をそのまま適用**します（100%）。`uidmap` で元 JSON の該当箇所へ書き戻し、DataSet／Magic ETL などの英語 UI 用語はそのまま残ります。
- **非 JSON（docx/xlsx/txt）**は、プロジェクト TM（メイン＋サブ）の完全一致を文単位で適用します。**TEP 書き戻し（§8a）後に実行**すると確定訳で埋まります。TM に無い文は既定で原文のまま（`--mark-missing` で `〔未訳〕`）。
- **保存先を選択**できます：出力時のダイアログで **2_For review / 3_Final / 任意のフォルダー** から選びます（既定は 2_For review）。
  - ⚠ **2_For review に元ソースと同名の成果物があると上書きになります**（元ファイルを残したいときは 3_Final か別フォルダーを選択。ダイアログにも注意書きが出ます）。
- 中間生成物は常に `_kotonoha`、最終の翻訳版は選んだ保存先に出力されます（§11）。

## 7. 中間ファイルの形式

**`combined.mt-todo.json`**（②が出力／③一括翻訳の入力）
```json
{ "count": 3079,
  "articles": [ {"art":"TM-Match-Explorer-DomoStats Connector","html":"…\\….html",
                 "title":"DomoStats Connector","source":"…","segs":1703,"mt":1695} ],
  "segments": [ {"gi":0,"art":"TM-Match-Explorer-DomoStats Connector","i":2,
                 "en":"This article…","pct":32.0,
                 "glossary":[{"en":"DomoStats","ja":"DomoStats"}],
                 "tm_candidates":[{"en":"this article covers…","ja":"この記事では…","pct":"47.1"}]} ] }
```
- `gi` … 全記事横断の**グローバル通し番号**。`art`＋`i` … どの記事の何行目か。
- `glossary` … 指定 TM（Product TM）由来の用語ヒント。`tm_candidates` … **指定 TM（メイン/サブ/Product）の該当既訳（最も近い候補・類似度順に上位5件）**。MT 作成時に外部AIがこれらを参照し、TM に沿った訳にする（全プロジェクト共通）。

**`combined.mt-done.jsonl`**（Claude が作成／③一括反映の入力。1行1レコード）
```
{"gi":0,"ja":"この記事では、DomoStats コネクターについて…"}
```
- キーは `gi`（推奨）。`{"art":..,"i":..,"ja":..}` 形式も受理。単一モードは `<記事>.html.mt-done.jsonl`（`i` キー）。

**スペル・文法チェック（B・Claude 点検）** … `_wip\<記事>.check-todo.json`（ツールが書き出し／SPELL ON 時は訳文欄フォーカス外れで自動更新）
```json
{ "art":"Creating DataFlows in Magic ETL", "savedAt":"…", "instructions":"…",
  "items":[ {"i":0, "en":"Select the card you want to resize.", "ja":"サイズ変更したいカードを選択します。"} ] }
```
`_wip\<記事>.check-done.jsonl`（**Claude が作成**／「結果を反映」で取り込み・1行1レコード・問題なしの item は書かない）
```json
{"i":0,"issues":[{"field":"ja","msg":"句点が不足","suggest":"…します。"}]}
```
- `field` … `en`（原文）/`ja`（訳文）。`msg` 指摘・`suggest` 修正案。反映すると該当セグメントに **⚠**（カーソルで詳細・プレーン表示）。

## 8. マッチ区分・UI・XLIFF 出力

マッチ区分は **beta1 と同一**（ICE / 100% / 95-99 / 85-94 / 75-84% はTM訳の適用、`<=74%` は MT）。ブラウザ UI（サマリー・フィルター・編集モード・localStorage 自動保存・XLIFF 1.2 書き出し）も基本は beta1 と同じ。

**「確定（Confirm）」**（beta2〜）：各行の確定チェックボックス、「表示中を一括確定」、「確定済みのみ」フィルター。確定は `localStorage` に自動保存。確定行を**編集すると確定は自動解除**。XLIFF 書き出し時、確定行は `state="final"` ＋ `<note>` に `| confirmed`。**この確定行だけ**が §8a の書き戻し対象です。

**翻訳履歴ペイン（Rev 3.00〜）**：編集画面の下部に、表＝全幅、その下に **履歴ペイン（左）｜用語ペイン（右）** を配置。行をクリックすると、その原文の**過去訳＋更新日時**が新しい順に履歴ペインへ表示されます（→ §8c）。用語ペインは領域のみ（用語集表示は今後）。

## 8a. TEP 確定 → Live_TM 書き戻し（Pass 4・蓄積型）

「作業者が確定するまで書き戻さない」方針です。ブラウザで確定 → XLIFF 書き出し → `tm_writeback.py`（または [7]／サーバーモードの「ツール ▾」）で Live_TM に書き戻します。

```powershell
python tm_writeback.py --xliff "…\<記事>.xliff" --customer University --live-dir "…\Kotonoha\Live_TM"
# 複数一括: --xliff a.xliff b.xliff … / --xliff-dir "…\フォルダー"
# まず内容確認だけ: --dry-run
```

| 引数 | 説明 |
|---|---|
| `--xliff` / `--xliff-dir` | 書き出した XLIFF（複数可）／フォルダー（再帰） |
| `--customer` | `University`/`Website`/`Marketing`/`Product`/`Subtitle`。省略時は Master のみ |
| `--project-tmx` | プロジェクトTMのパスを明示指定（`--customer` の対応表を上書き） |
| `--master` / `--live-dir` | Master TMX のパス／Live_TM フォルダー |
| `--dry-run` | 変更せず、追加（new）/同一（same）件数だけ表示 |

**動作（Rev 3.00 で蓄積型に変更）**：
- 確定行（`state="final"` または note に `confirmed`）で訳文が空でないもののみ書き戻し。
- 書き込み先は **Master TMX（常に）＋プロジェクトTM（`--customer`／`--project-tmx`）**。
- **過去訳を上書き・削除しません**。同一原文に**新しい確定訳が来たら新しい版（TU）として追記**し、各 TU に更新日時（`changedate`）を付けます。**同一の訳**を再度書き戻した場合は版を増やさず日時だけ更新（重複 TU は作りません）。→ 蓄積の詳細は §8c。
- ICE 用の前後文脈（`x-previous-source-text`/`x-next-source-text`）を各 TU に付与。
- 確定が 0 件、かつ対象TMXが未作成なら**ファイルを作りません**。
- **サーバーモードの「ツール ▾ → 書き戻し」は、本実行の直前に書込先 TMX を日付きバックアップ**します。

**プロジェクトTM名（Live_TM 内・日付なし正規名）**：`Domo_Domo University-en_US-ja_JP.tmx` 等。Master は `Domo_Domo-Master.tmx`。

## 8c. 翻訳履歴（TM蓄積型）と編集画面の履歴ペイン

**目的**：過去の翻訳を失わず、いつでも参照できるようにします。

- **蓄積（書き戻し）**：§8a のとおり、同一原文に対する確定訳は**上書きせず版として TM（TU）に蓄積**されます（各版に更新日時）。
- **マッチング（Pre-translation）**：同一原文に複数版があるとき、索引は**最新版（更新日時が最大）の訳**を 100%/あいまい一致に採用します（**newest-wins**）。過去版はマッチ結果には使われません（履歴として保持されるだけ）。単一版の原文は従来どおりで、挙動は変わりません。
- **履歴ペイン（編集画面）**：行（セグメント）をクリックすると、**左下の「翻訳履歴」ペイン**にその原文の過去訳が**新しい順**（最新を強調・更新日時付き）で一覧表示されます。過去訳が無い原文は「過去訳はまだありません」。
- **レイアウト**：セグメント表＝全幅、その下に **翻訳履歴ペイン（左）｜用語ペイン（右）**。画面が狭いときは縦積み。**用語ペインは領域のみ確保**（用語集表示は今後実装）。

> 既存の Live_TM は現状「原文に 1 訳」です。**今後の書き戻しから版の蓄積が始まり**、再翻訳した原文だけ版が増えます（1 回きりの原文は 1 版のまま）。各書き戻し前の自動バックアップ（サーバーモード）とあわせ、過去の状態はファイルとしても残ります。

## 10. 制約・注意点

- 元 `.mdx` は直接上書き不可（ブラウザのセキュリティ）。編集は XLIFF 書き出し→別途反映、または **元形式で出力**（§5c・現状 .txt）。
- 静的 `file://` では作成・実行・編集・各ツールは使えません（**[D] サーバーモード**を使用）。ダウンロードは `file://` で開いた場合に機能。
- ICE は文脈プロパティ付き TMX でのみ判定可。MT は下訳（TEP 前提）。類似度は文字ベースのため XTM 実測と多少ずれます。
- 書き戻しは **XTM（元TM・読み取り専用）には一切書きません**。書き込み先は Live_TM の Master／プロジェクトTM のみ。
- **蓄積型**：同一原文の過去訳は TM に版として残り、マッチには最新版を使います（§8c）。TM が再翻訳のたびに少し大きくなります（再翻訳した原文のみ）。
- 書き戻しキーは**ソース文字列（前後空白除去）**。大文字小文字・記号差は別エントリー扱い。
- Live_TM の TMX は本ツールが管理する形式です。外部ツールで手編集した TMX を混ぜる場合は形式差に注意。
- サーバーモードは **127.0.0.1 限定＋トークン認証**（他ホスト・他サイトからはアクセス不可）。重い処理は同期（完了までタブを閉じない）。

## 11. beta5 以降の追加機能（beta5 〜 7.0）

### 11.1 起動（ハブ）とタブ・TEPウィンドウ
- **`起動_Kotonoha-ハブ.bat`** をダブルクリックで `projects.py serve` が立ち上がり、ブラウザが自動で開きます（= §5b サーバーモードの入口）。
- ダッシュボード上部の**親タブ**：左端に常設の「**プロジェクト**」（閉じられない）。記事を「実行」または「開く」とその**プロジェクト名のタブ**が開き、各タブは **×** で閉じられます。タブが 0 件になると、空の **「TM-Match-Explorer」** タブ（空の翻訳／サマリー）を表示します。
- **TEPウィンドウ**（＝記事ごとの編集画面。旧称「プロジェクト名ウィンドウ」）: ヘッダー右側（テーマ切替の左）に **再読み込み / 別タブで開く / 保存して閉じる / TEP完了 ✓** を配置。「保存して閉じる」は作業内容を保存してからそのタブを閉じます（編集/確定があれば TM 書き戻しを確認・§11.15）。「TEP完了」は確定訳を TM へ書き戻して完了にします（§11.15）。作業エリア最大化のため、タブ周りの余白を圧縮し、ステータス文言（解析・Pre-translation済み／自動保存）は**親タブのツールチップ**（マウスオーバー）に移動しました。

### 11.2 プロジェクトの作成は利用者のみ／中間生成物は `_kotonoha`
- **プロジェクトを作るのは利用者だけ**です。実行して生成された記事を、ツールが勝手に別プロジェクトとして台帳へ登録することはありません（生成物はそのプロジェクトの `artifacts` として記録）。
- 実行で生成される**中間生成物**（作業ファイル `<記事>.html`・`uidmap`・`combined.mt-todo.json`・manifest・mt-done 等）は、各プロジェクトフォルダー配下の **`_kotonoha`**（無ければ自動作成）に保存されます。別プロジェクトでも、その親プロジェクトフォルダー下の `_kotonoha` で作業します。
- 行の **[詳細]** を押すと、その行の下にサブセクションが開き、**作業サマリー**（状態・ソース数・各 TM・生成記事数など）と **`_kotonoha` の中身**（ファイル一覧）が表示されます。作業ファイル(HTML)は「開いて編集」、各ファイルは「開く」でエクスプローラー表示。「フォルダーを開く」で `_kotonoha` を開きます。

### 11.3 配信は「生成ファイルそのまま」＝最新 UI は「実行」で反映
- ハブで作業ファイルを開くと、**生成された `.html` をそのまま配信**します（内容はファイルと完全一致。サーバー用トークンのみ付与）。
- そのため、**テンプレート（UI）を更新しても既存の作業ファイルには反映されません**。対象記事を **「実行」で再生成**すると、現行テンプレートで作り直されて最新 UI になります。

### 11.4 出力先の選択（§5c 参照）
- 出力時に **2_For review / 3_Final / 任意フォルダー** から保存先を選べます（既定は 2_For review）。2_For review は元ソースと同名だと上書きになる点に注意。

### 11.5 MT の任意化（反映先の制御）／MT は指定 TM を参照
> このツールに MT 翻訳エンジンは内蔵していません。MT は外部 AI（Claude 等）で `mt-todo` を翻訳→ `mt-done` を**反映**する人手フローです。ここでの「MTを実行」は**反映先の制御**です。
- **MT は指定 TM を必ず参照**：`mt-todo` の各セグメントに、用語ヒント（`glossary`＝Product TM 由来）に加えて **`tm_candidates`（指定 TM の該当既訳＝最も近い候補・類似度順に上位5件）** を同梱します（全プロジェクト共通）。外部AIはこれらを参照して TM に沿った訳を作成します。≤74% は完全一致が無い区分のため「該当既訳」は最も近い候補の利用です。
- **作成ダイアログの「MTを実行」チェック**（ブラウザに記憶し次回の作成にも引き継ぎ）：
  - **ON**：既訳のない（≤74%）セグメントの MT を**翻訳欄に反映**します（従来どおり）。
  - **OFF**：翻訳欄は**英語のまま**表示し、反映した MT の結果は**翻訳履歴ペイン**に入り、左上に日付でなく **"MT"** と表示されます。作業ファイルのツールバー **「MTを実行する」** で、履歴の MT を後から翻訳欄へまとめて反映できます。
- **翻訳欄の右クリック →「MTを挿入」**：現在の訳文はそのまま、**末尾に MT を追加**します（1 セグメントずつ）。

### 11.6 すべて確定（翻訳タブ）
- 確定列のヘッダーにある **「すべて確定」** チェックで、**現在表示中（フィルター後）**の行をまとめて確定／解除できます（訳文が空の行は対象外）。フィルターを変えると状態は同期します。

### 11.7 用語
- UI・ドキュメントで用語を統一：**Pre-translation（下訳）＝ TM訳の適用＋MT**、**「流し込み」「MT注入」は使わない**（「MTを反映」）、**TEP は作業（工程）**でファイル名ではない（生成 HTML は「**作業ファイル／編集画面**＝TEPウィンドウ」）。

### 11.8 TM タブ（TMエントリの編集）
ダッシュボードのサブタブ **プロジェクト / 用語管理 / TM** の「**TM**」。プロジェクトが参照する TM を一覧し、**書込可能TM**（`_kotonoha` 系の Main-TM 等。巨大な **XTM は読み取り専用**・サイズ上限超も編集不可）の**エントリを一覧・検索・編集（EN+JA）・削除・追加**できます。
- 上部で **TM を選択**、検索ボックスで **EN/JA 部分一致**で絞り込み。各行の **編集**（EN/JA をモーダルで修正）・**削除**、**＋ エントリ追加**。
- **書込前に日付きバックアップ**（`<TM名>.bak_YYYYMMDD-HHMMSS.tmx`）を自動作成。蓄積型（同一原文の複数版）を保持します。
- TMX を編集すると索引の指紋が変わり、次回の「実行」でキャッシュが自動再構築されます（XTM は編集対象外なので影響は限定的）。

### 11.9 Reference ボックス（参照ペインの統合・ドラッグ&ドロップ）
TEPウィンドウ翻訳タブの下部に、**翻訳履歴 / 用語集 / Concordance search**（準備中）の3ペインを内包する **Reference ボックス**（名称は非表示）。
- 各ペインの**ヘッダーをドラッグ&ドロップ**して位置を入れ替え（順序はブラウザに保存）。
- 空きスペースを作らず**自動拡張**（3ペイン時は上段2＋下段1、または画面幅に応じて縦積み）。

### 11.10 用語集ペイン（原文/訳文表示・編集）
翻訳タブの用語集ペインで、行をクリックするとその**セグメントの EN 原文・JA 訳文**を表示。原文/訳文（または本文表）で**文／句／単語を選択**すると追加フォームの EN/JA に流し込まれ、**EN/JA を編集して用語集に追加**できます。**既存用語は EN/JA をインライン編集（保存）・削除**（サーバーモード時）。用語集は全プロジェクト共通の `_terms.tsv`。

### 11.11 Concordance search（対訳用例の横断検索）
Reference ボックスの **Concordance search** ペインで、指定した TM を横断して対訳用例を検索します。
- **検索対象TM**: 既定はその記事の所属プロジェクトの TM（メイン/サブ/Product）。チェックで対象を絞り、**＋ TMを追加**（既知TM一覧から選択）・× で増減できます。各 TM に **索引:✓/未** を表示。
- **索引を作成**: チェック済みで未構築の TM について、専用の検索索引（`conc_<指紋>.pkl`）を作成します（大きい TM は初回のみ時間がかかり、以降は高速。索引キャッシュと同じ TM 管理フォルダーに保存）。
- **検索条件**: 検索語（スペース区切りで複数）＋ **フィールド（EN+JA / ENのみ / JAのみ）**＋ **AND/OR**＋ **大小区別**＋ **正規表現**。
- **結果**: **英語 / 日本語訳 / TM名 / 更新日付** の表。未構築の対象TMがあれば警告し「索引を作成」を促します。件数上限で打ち切り表示。

### 11.12 履歴タブ（操作の自動記録）／説明文の撤去・ツールチップ化
- 各ビューのタイトル下にあった**長い説明文は撤去**し、作業エリアを広く使えるようにしました。代わりに各**ボタン・チェックボックス・検索欄・タブ**にマウスオーバーで出る**ツールチップ**で使い方・内容を表示します。
- プロジェクトウィンドウのサブタブ **プロジェクト / 用語管理 / TM / 履歴** の「**履歴**」。ツールの操作（**作成・実行・出力・状態変更・削除・MTを反映・TM書き戻し・用語/TM編集・Concordance索引作成** など）を **`_history.json`** に**自動記録**し、**日付・種別・作業内容**を新しい順に一覧表示します。
- 各行の **メモ**欄にコメントを入力して「**保存**」、不要な履歴は「**削除**」できます。検索欄で作業内容・メモ・プロジェクト名を絞り込めます。`_history.json` は環境依存のため Git 管理外（自動生成）。

### 11.13 行アクションの「再開」ボタン（再解析せず既存の作業ファイルを開く）
- **一度「実行」したプロジェクト**（生成済みの作業ファイル＝`artifacts` の実体がある行）では、行のボタンが **「再開」** になります。
- **「再開」** は、再解析をせずに **既存の作業ファイル（編集画面＝TEPウィンドウ）をそのまま開きます**。前回の続きをすぐ始められます。
- ソースや TM を変えて作り直したいときは、隣の **「再解析」** を押します（＝従来の「実行」。現行テンプレートで作業ファイルを再生成します）。
- まだ一度も実行していないプロジェクトでは、従来どおり **「実行」** が表示されます。

### 11.14 UI 状態のサーバー側保存（別ブラウザ・再起動後でも復元）
- 開いていた **TEP タブの一覧とアクティブタブ**、サブタブ（プロジェクト/用語管理/TM/履歴）、**Reference ボックスの各ペインの順序・サイズ・列数・ボックス高さ**、フィルター、テーマなどの **画面の状態** を、サーバー側の **`_uistate.json`** に保存します。
- そのため、**別のブラウザや別のPCで開き直しても、ツールを再起動（ポート番号が変わっても）しても**、前回の画面状態が復元されます（従来はブラウザごとの `localStorage` 依存で、環境が変わると失われていました）。
- 仕組み: 配信ページ冒頭で前回状態を読み込み、以後の画面状態の変更を自動でサーバーへ同期します（`kotonoha-*` の設定が対象）。保存は自動で、特別な操作は不要です。
- 前回すべてのタブを閉じて終了していた場合は、起動時に空の **TM-Match-Explorer** を表示します。
- `_uistate.json` は環境依存のため **Git 管理外**（自動生成）。

### 11.15 TEP完了（確定訳をマッチ元TMへ個別書き戻し＋完了）
編集画面（TEPウィンドウ）ヘッダーの **「保存して閉じる」の右**に **「TEP完了 ✓」** ボタンがあります。翻訳作業を締めるときに押します。1クリックで、**確定済みの訳をTMへ書き戻し → プロジェクトを「完了」に → タブを閉じる** までを行います（従来の「確定→XLIFF書き出し→ツール▾→書き戻し」を集約）。
- **書き戻し対象＝確定済みセグメントのみ**。未確定が残っている場合は **警告ダイアログ**（「未 N 件は書き戻されません。続行しますか？」）が出て、**続行すると確定分だけ**書き戻します。
- **書き戻し先＝各セグメントが実際に一致してきたTM（マッチ元TM）へ個別に**。一致の無いセグメント（MT／無一致）や、マッチ元が書込不可（XTM 等の読み取り専用）・プロジェクト外のものは **メインTM** へまとめます。
- 蓄積型（既存訳を残して**新しい版として追記**・上書きしない）で、**書込前に各TMXを日付きバックアップ**します。完了すると結果（書込TM数・件数・メインTMへ回した件数）を通知し、操作は**履歴タブに「TEP完了」**として記録されます。
- あとで再度 TEP を行うときは、プロジェクトタブの **「再開」** で開き直します（§11.13）。
- **マッチ元TMへの個別ルーティングを効かせるには、対象記事を本アップデート後に一度「実行／再解析」して作業ファイルを再生成**してください（それ以前の作業ファイルには由来TM情報が無いため、確定分はすべてメインTMへ回ります）。手動書き戻し（ツール▾「TEP 結果を TM に書き戻す」）も従来どおり利用できます。

**途中保存／保存して閉じる での TM 書き戻し（任意）**: **途中保存** または **保存して閉じる** を押したとき、**編集または確定が1件以上あれば**「**TMに変更内容を保存しますか？**」（はい/いいえ）を確認します。
- **はい**：**確定済み（approved）のセグメントのみ**をマッチ元TMへ書き戻します（その記事のみ・**ステータスは「完了」にしません**＝作業中のまま）。未確定は書き戻しません。
- **いいえ**：従来どおり作業内容を保存（保存して閉じるはタブも閉じる）だけで、TMには書きません。
- TEP完了ボタン（上記）は引き続き「全セグメント＋完了＋閉じる」です。自動保存・Ctrl+S では確認は出ません（途中保存・保存して閉じる のクリック時のみ）。

### 11.16 プロジェクトのステータス（作成済／作業中／レビュー中／完了）
プロジェクト一覧の **状態** 列は次の4値です。フィルターチップと「編集」ダイアログのセレクトで切り替え・絞り込みができます。
- **作成済**：新規作成した直後（まだ実行していない）。
- **作業中**：「実行」で作業ファイルが生成された後（翻訳・編集中）。
- **レビュー中**：任意（レビュー段階を手動で示すとき）。
- **完了**：**TEP完了**で確定訳をTMへ書き戻した後（「完了を隠す」で一覧から隠せます）。
- ※**「完了」は手動では設定できません**。TM への書き戻しを必ず伴わせるため、**完了は TEP完了 でのみ**付きます（「編集」ダイアログのセレクトに「完了」は出ません。すでに完了の行は、作業中などへ**戻す**ことは可能）。
### 11.17 オートプロパゲーション（同一原文への自動伝播）
翻訳タブのツールバーに **「自動伝播」** チェック（既定ON）があります。オンのとき、あるセグメントを **「確定」した瞬間**に、**同じ記事内で原文が完全一致（タグ含め文字単位で同一）する他のセグメント**へ同じ訳を自動で流し込みます。ボタン名・ラベル・定型文など繰り返しの多い内容で入力の手間を省けます。
- **対象＝原文が 100% 完全一致**のセグメントのみ（あいまい一致には伝播しません）。
- **伝播先は訳を入れるだけで、確定はしません**（各自でレビューして確定）。
- **伝播で訳が入ったセグメントは、Match 列に「R」**（Repetition＝繰り返し）と表示されます。そのセグメントを**手動で編集すると「R」は消えます**（通常のマッチ表示に戻ります）。「R」の状態は保存され、別ブラウザで開き直しても保持されます。
- **上書きの扱い**：伝播先が **未編集・未確定**なら訳を埋めます。すでに **異なる訳**（手動編集済み／確定済み）を持つ場合は **「N 件を上書きしますか？」と確認**し、**キャンセルすると既存訳を保持**します。
- 伝播が起きると「同一原文 N 件に訳を伝播しました」と通知します。設定（ON/OFF）はブラウザに保持されます（別ブラウザでも維持）。
- オフにすると従来どおり、確定しても他セグメントへは何も流し込みません。

### 11.18 「i」ボタン（使い方・保存場所の情報）
作業領域を広く取るため、各ページ下部にあった**説明文（footer）は撤去**しました。代わりに **プロジェクト一覧ボックスの右上に「i」ボタン**を置き、クリックすると次の内容を**ダイアログ**で表示します。
- TEP の進め方（Japanese（Pre-translation）列を編集して確定 →「XLIFF 書き出し」。確定行だけが Live_TM＝Master／プロジェクト TM への書き戻し対象。TM 行は TM 訳、MT 行は AI 下訳。編集・確定はブラウザに自動保存。確定行を編集すると確定は解除され再確定が必要）。
- 保存場所など（台帳 `_projects.json`／用語集 `_terms.tsv`〔全プロジェクト共通〕／この一覧は `projects.py dashboard` で生成。開き直すと最新）。

### 11.19 承認ステータス（approved / notapproved）
TM の各 TU が持つ **`x-xtm-status`（approved＝承認済み / notapproved＝未承認）** を「翻訳の信頼度の目安」として活用します。
- **書き込み（TEP完了時）**: プロジェクト完了で**全セグメント**を各セグメントの**マッチ元 TM**へ書き戻し、**確定行＝approved／未確定行＝notapproved** を付与します。マッチ元が XTM（大）なら**その XTM の末尾へ追記**（既存TUは不変・全書き直ししない）、書込可能な小 TM は蓄積マージ、無一致/MT やマッチ元が対象外のものは**メイン TM** へ回します。書き込みは**排他ロック**で直列化します。
- **読み込み（下訳の制御）**: 新規作成ダイアログの **「未承認のセグメントも使用」** チェック（既定 ON・前回値を記憶）。**OFF にすると approved の既訳だけ**で Pre-translation します（notapproved を索引から除外）。切替時は初回の解析で索引を作り直します。
- **表示**: 翻訳タブの Match 列に、マッチ元が未承認なら **「未承認」バッジ**を表示します（approved・status無しは通常表示）。
- 注意: 未確定も notapproved として書くため、**ファジー行の既定訳（別原文の既訳）や MT 未反映の英語**も入り得ます（§11.20 の要確認警告で気づけます）。XTM へ書くと**次回解析でその XTM が再索引**されます（大きい TM は数分）。

### 11.20 「⚠要確認」警告（数値・タグの不一致）
原文と訳文で **数値（全半角正規化して比較）や `{n}` タグが食い違う行**を検出し、Match 列に **「⚠要確認」** を表示します（例: 原文 `OAuth 2.0` に対し訳が `1.0`）。
- ツールバーの **「要確認のみ」** で該当行だけ表示、横に件数を表示。
- あくまで**疑い（非ブロッキング）**で、書き込みは妨げません。TEP完了の確認ダイアログにも件数を表示します。

### 11.21 TM バックアップ（手動確認式・自動では作成しない）
XTM への追記に備え、**TM のバックアップ**を取れます（TM タブ）。
- **「TMバックアップを作成」** チェック＋**頻度**（一度だけ／毎日／毎週／毎月／しない）。設定は保存されます。
- **自動では作成しません**。ツール起動時に頻度の期限が来ていれば**作成するか確認**し、作成時は**保存先フォルダーをダイアログで指定**します。「**今すぐバックアップ**」ボタンでも実行できます。
- 対象は **Kotonoha が書き込む TM（メイン TM＋プロジェクト参照の TM）**。保存先に `Kotonoha-TM-backup_日時` フォルダーを作ってコピーします。

### 11.22 クラウド（OneDrive）TM の保存/読み込み
TM を**チーム共有のため OneDrive 内の指定フォルダー**に保管・取得できます（ファイルコピー・フォルダー単位も可。同期は OneDrive アプリ任せ）。
- **クラウドTMフォルダーの指定**（TM タブ）: 「クラウドTMフォルダー」の **「変更」** で OneDrive 上の共有フォルダーを選びます（保存されます）。
- **TM タブの「クラウド操作 ▾」**:
  - **選択中の TM をクラウドへ保存**（単一ファイルをコピー・上書き）。
  - **フォルダーごとクラウドへ保存**（選んだフォルダー内の全 `.tmx` をコピー）。
  - **クラウドから読込**（クラウドの `.tmx` を選び、保存先フォルダーへコピー）。
  - **フォルダーごと読込**（クラウドの全 `.tmx` を選んだローカルフォルダーへ）。
- **プロジェクト作成/変更時に指定**: 作成ダイアログ・**「編集」ダイアログ**のメイン/Product/サブ TM に **「クラウドから」** を追加。クラウドフォルダー内の `.tmx` 一覧から選んで、その OneDrive 上の TM をそのままプロジェクトの TM に設定できます（**編集ダイアログから TM を変更できるようになりました**）。
- コピーは**上書き**（最新優先）。OneDrive 配下はアプリが自動同期するため、TM を直接クラウドフォルダーに置いてプロジェクトで参照すれば、そのまま共有されます。

### 11.23 作業ビューのレイアウト（スクロール・リサイズ・固定）と TM タブ表記（beta6.31）
翻訳作業（TEP）画面の作業ビューを見やすく調整しました。設定は**配信済みの作業ファイル(HTML)** とテンプレート（`TM-Match-Explorer-demo.html`）の**両方**に反映されます（`/article` 配信はファイルそのままのため、既存の作業ファイルにも直接適用済み）。

- **単一スクロール基調**：作業ビュー全体を縦に伸縮させ、縦スクロールは原則**ページ側の1本**に集約。
- **タブ行・操作行のスティッキー固定**：下へスクロールしても、ビュー切替タブと検索/フィルター操作行は上部に残ります。
- **TEP（セグメント）ペインのリサイズ**：ペイン右下のつまみで**高さをドラッグ調整**。内部の縦スクロールバーは、設定した高さを内容が超えたとき（**必要時のみ**）表示。
- **リファレンス各ペイン（履歴/用語/Concordance）**：**リサイズ可**（幅・高さ）。内容がはみ出すときのみ内部スクロールバーを表示。リサイズ後の幅/高さは保存され次回復元。
- **「○ / ○ セグメント」カウントの移動**：独立行から**操作行（「前回保存」と同じ行）の右端**へ移動し、縦スペースを節約。
- **ページ（ブラウザ）の縦スクロールバーを非表示**：見た目を整えるためページ右端の縦バーのみ非表示（`html`/`body` 限定）。**ホイール/キーボードでのスクロールは可能**で、各ペイン内のスクロールバーには影響しません。

**TM タブの表記**：TM 編集タブのドロップダウン・状態表示の「読み取り専用」を**「一括更新」**に変更しました。XTM 等の大容量/公式コーパスは**個別編集不可**（下書きで汚染しない方針・サイズ上限 60MB 超も対象外）ですが、**TEP完了時に承認済みを末尾追記**する実態に合わせた表記です。さらにドロップダウンの役割ラベルを簡素化し、**メイン TM 以外は TM 名のみ**表示（「Product TM」「サブ TM」ラベルは非表示）。

### 11.24 作業ビューの機能拡張（拡大/縮小・ポップアウト・連動）と Concordance ドロップダウン（Ver.7.0）
**用語**：編集対象のセグメント編集ペインを **TEPペイン**、各プロジェクトの編集タブを **TEPタブ** と呼びます（TEPタブ ⊃ TEPウィンドウ ⊃ TEPペイン＋リファレンスペイン）。

- **拡大/縮小**：各ペインのヘッダー右端のトグル（▾/▸）で、ペインを**ヘッダー1行に縮小**／**クリックで拡大**。TEPペインにはヘッダー行 "TEP" を新設。
- **ペインのポップアウト**：ヘッダー/配置バーの **⧉（別タブ）・⧈（別ウィンドウ＝1200×800）** から開きます。
  - **TEPペイン単独**（`?view=tep`）：セグメント表＋操作行（検索/フィルター/確定/XLIFF）のみ。
  - **リファレンス3ペインまとめ**（`?view=ref`）：翻訳履歴・Concordance・用語集をまとめて表示。
  - 配信は**標準モードの完全ドキュメント**なので、別タブ/別ウィンドウ単体でも崩れません。
- **連動**：リファレンスを別ウィンドウにしても、メインの **TEPペインで選択したセグメントに翻訳履歴/用語集が連動**します（同一オリジンの **BroadcastChannel**＝`kotonoha-seg:<pid>` で選択番号を共有。別プロジェクトは別チャンネル）。Concordance は選択に依存せず独立動作。
- **ハブのタブ**：ダッシュボードの **「プロジェクト」タブ**と各 **TEPタブ**の右に **⧉/⧈**。プロジェクトタブはハブ `/`、TEPタブはその記事URLを別タブ/別ウィンドウで開きます。
- **Concordance の検索対象TM**：**ドロップダウン**（「検索対象TM (選択/総数) ▾」）に変更。パネルは固定配置オーバーレイ（ペインの overflow に切られない）、**下部に固定の「＋ TMを追加」**、**横に「Indexを作成」**。表記は「索引」→**「Index」**に統一。
- **ラベル**：区分「再利用」→**「Pre-Trans.」**、トグル「編集済みのみ」→**「編集済」**、「確定済みのみ」→**「確定済」**。各ペインのヘッダー（ツールバー）はスリム化。

> ブラウザ補足：Chrome で別タブが「黒字テキストのみ」になる場合は、**拡張機能（Dark Reader 等）が localhost(127.0.0.1) の CSS を剥がしている**ことが原因です（Edge／シークレットでは正常）。該当拡張を 127.0.0.1 で無効化するか、Edge で利用してください。

### 11.25 スペル・文法チェック／英語リアルタイム文法／翻訳履歴の英語差分／フォント自ホスト（Ver.7.0 内・2026-11-19）
機密（Domo コンテンツ）を**外部サービスへ送信しない**方針で実装。操作行の **「スペル・文法チェック」チェックボックス（既定OFF）** で一括 ON/OFF。

- **(A) ブラウザ内蔵スペルチェック**：ON で訳文欄に `spellcheck` を付与し、英語スペル等の波線をリアルタイム表示。※内蔵の「高度/クラウド」や拡張機能は OFF 推奨（機密の外部送信回避）。
- **(1) 英語リアルタイム文法（LanguageTool・ローカル）**：`%LOCALAPPDATA%\Kotonoha-LT`（ポータブル JRE 21＋LanguageTool 6.6）をハブ起動 bat が自動起動（`127.0.0.1:8081`）。ハブの **`/api/lt` 同一オリジンproxy**経由で、訳文編集を**デバウンス点検→画面下部パネル**に指摘＋修正案を表示（方式P）。機密はハブ→LT のローカル内のみ＝外部送信なし。英語文法は高品質、**日本語文法は簡易**（Word級ではない）。
- **(2) 日本語＝半自動 Claude 点検**：訳文欄のフォーカス外れ 2 秒で `_wip\<記事>.check-todo.json` を自動更新。**Claude が点検**し `_wip\<記事>.check-done.jsonl`（各行 `{"i":index,"issues":[{"field":"en|ja","msg","suggest"}]}`）を作成→**「結果を反映」**で該当セグメントに **⚠**（カーソルで指摘＋修正案・プレーン表示）。MT フローと同型の手介在・外部送信なし。
- **翻訳履歴ペインの英語差分**：MT セグメントのあいまい候補で、**過去英語＝正／現在原文の新規・変更語を取り消し線**表示（過去訳の流用判断を補助）。
- **フォントの自ホスト**：Google Fonts 外部リンクを廃止し、同梱 woff2（`fonts\`・SIL OFL）を `/fonts/` から配信＝記事表示時の**外部通信ゼロ**。

> 運用：**テンプレート（`TM-Match-Explorer-demo.html`）を編集 → 記事を再生成**（`python projects.py run --id <pid> --engine … --template … --cache-dir …`。MT は自動再反映）で生成記事に反映。LanguageTool/JRE は repo 外（`%LOCALAPPDATA%\Kotonoha-LT`）に置き、ハブ起動 bat から起動（黒いコンソールを閉じると LT もハブも停止）。

## 12. セキュリティ {#security}

本ツールは**ローカル専用**で、機密（Domo）コンテンツは原則ローカルに留まります。以下に簡易アセスメントと実装済みの対策を示します（運用方針：新機能・変更のたびに攻撃面を点検し、懸念は報告・対策・残リスクを明記）。

### 12.1 前提・信頼境界
- ハブは **127.0.0.1 限定バインド**（LAN/外部へ非公開）。`/api/*` は**ランダムトークン `X-KT-Token`（カスタムヘッダ）必須**＝ブラウザ経由の CSRF を遮断。外部プロセス起動は**リスト形式**（`shell=True` なし）＝シェルインジェクション不可。
- LanguageTool もローカル（`127.0.0.1:8081`）。ハブ経由の `/api/lt` proxy で呼び、**機密テキストは外部へ出ない**。
- **外部送信されるのは**：MT／スペル文法チェック(B) の「Claude 点検」パス（＝翻訳本文を Claude に渡す／既存 MT と同じ運用）のみ。LanguageTool・内蔵スペルチェック(基本)・フォントは**外部送信しない**（内蔵スペルの「高度/クラウド」モードや一部ブラウザ拡張のみ例外＝OFF 推奨）。

### 12.2 実装済みの対策（2026-11-19）
| 項目 | リスク | 対策 |
|---|---|---|
| スクリプト埋め込み XSS | `window.__KT`/`__UISTATE` のJSONに `</script>`/`<` が混入すると `<script>` を抜け任意JS実行 | `_js_embed()` で `<`→`<`・`>`・`&`・U+2028/2029 をエスケープ |
| DNS リバインディング | 遠隔サイトが 127.0.0.1 に再バインドし同一オリジン化→内容読取 | `_host_ok()` で Host を 127.0.0.1/localhost/::1 限定（`do_GET`/`do_POST` 冒頭で 403） |
| CSV/Excel 式インジェクション | 用語が `= + - @` 始まりだと Excel で数式実行 | `_csv_safe()` で先頭に `'` を付与（TSV/CSV/Xlsx） |
| 描画 XSS（継続方針） | TM/MT/Claude/LanguageTool 出力・入力を未エスケープで挿入 | すべて `esc()` して挿入。Claude の指摘は `title` 属性（プレーン）＝HTML実行不可。履歴差分・LT結果も各断片 `esc()` |
| パストラバーサル | `/article?path=`・`/fonts/` で任意ファイル読取 | `/article` は `abspath`＋プロジェクトルート内包＋`.html` 限定、`/fonts/` は basename＋`.woff2/.css` 限定 |
| 外部通信 | 機密の外部流出・活動の外部露出 | Google Fonts を**自ホスト化**（外部通信ゼロ）。文法チェックは**自ホスト LanguageTool**（外部送信なし）。Claude 点検のみ外部（承認運用） |

### 12.3 残リスク・運用上の注意
- **ローカル同一ユーザーの悪性プロセス**：`127.0.0.1` に到達できる同一ユーザー権限のプロセスは `GET /article`（トークン不要）で内容取得が理論上可能。ただしその種のプロセスはファイルへ直接アクセスでき**増分リスクは実質ゼロ**。主要な遠隔リスク（リバインディング）は §12.2 で遮断済み。
- **Claude 点検／MT の外部処理**：翻訳本文を Claude に渡す運用。社内の承認範囲で使用のこと。将来 API 自動化時は**キーをハードコードせず**環境変数/シークレットで管理し、外部送信を明示。
- **ブラウザ拡張（Chrome 等）**：Dark Reader 等が localhost の CSS を剥がす事象あり（Edge/シークレットでは正常）。内蔵スペルチェックの「高度/クラウド」や一部拡張は本文を外部送信し得るため、機密作業では OFF を推奨。
- **TM 書き戻しの整合性**：巨大 XTM への追記は中断時破損の恐れ→**書込前バックアップ**（手動確認式）で緩和。
