## 1. 変更履歴

本ツールと本マニュアルの変更履歴です。**仕様（機能）の変更は 1.1**、**本マニュアル自体の変更は 1.2** に記載します。

**Rev. no. の付け方**：`<整数部>.<小数部2桁>`（例 `1.00`）。
- **機能上の大きな変更・追加・削除**があったとき → **整数部を 1 上げる**（例 `1.23 → 2.00`）。
- **機能にあまり影響しない小さな変更**のとき → **小数部に 0.01 を加算**（例 `1.00 → 1.01 → 1.02`）。

## 2. 構成ファイル

| ファイル | 役割 |
|---|---|
| `起動_Kotonoha-ハブ.bat` | **ワンクリック起動**（`projects.py serve` ＋ブラウザ自動）。通常はこれを使う。 |
| `TM-Match-Explorer.bat` | 旧・メニュー式ランチャー（単機能の直接実行用）。 |
| `tm_index.py` | **①** 索引の構築＋pickleキャッシュ。過去訳の版履歴（`exact_hist`）＋**由来TM（`src_tm`）**を保持（TEP完了の個別書き戻し用）。 |
| `tm_match_analysis.py` | **Pass 1**：解析＋Pre-translation。②バッチ・③combined 対応。各セグメントに翻訳履歴 `hist`。`--run-mt`／TM一致訳の `<x>` タグ正規化／`META.runMT`。 |
| `inject_mt.py` | **Pass 3**：MTを反映。単一＋③batch（combined）。`META.runMT=false` のとき MT は訳欄でなく履歴（`{ja,mt:true}`）へ。 |
| `tm_writeback.py` | **Pass 4**：TEP確定行（XLIFF）を Live_TM へ書き戻し。**蓄積型**（過去訳を残す）。中核は `tm_writeback_lib.py`。 |
| `tm_writeback_lib.py` | 蓄積マージの中核（副作用なし）。手動書き戻し（`tm_writeback.py`）と **TEP完了**（マッチ元TMへ個別書き戻し）で共用。 |
| `ui_glossary.py` | 作業内容から UI 用語を抽出し用語集（CSV＋JSON）を作成。 |
| `projects.py` | プロジェクト台帳の管理・ダッシュボード生成・**サーバーモード（`serve`）**。版定数 `VERSION`（=beta5.01）。 |
| `doc_io.py` | 出力のための形式レジストリ（抽出／再挿入）。**.txt / .json（`json_io`）/ .docx（python-docx）/ .xlsx（openpyxl）**。 |
| `json_io.py` | Domoアプリ JSON の抽出／再挿入（HTMLタグを `{n}` 保護タグ化、`uidmap` で復元）。 |
| `tm_io.py` | TMタブ用の TMX 入出力（argparse非依存・蓄積型）。一覧/検索/編集/削除＋書込前バックアップ。 |
| `tm_concordance.py` | Concordance 検索用の専用キャッシュ＆検索（argparse非依存）。`ET.iterparse` で大TMも省メモリ解析、`conc_<指紋>.pkl`（索引キャッシュと同じ場所）。 |
| `doc_export.py` | プロジェクト TM を文単位で適用し、**元の形式で翻訳版を出力**（非JSONの往復ステージ）。 |
| `_projects.json` | プロジェクト台帳（**ユーザー作成のみ**・編集はツール経由。`run_mt`・`artifacts` を保持）。 |
| `_projects.html` | プロジェクト一覧ダッシュボード（静的／サーバーモード兼用・自動生成）。 |
| `TM-Match-Explorer-demo.html` | UIテンプレート（`--template` に指定・実行に必須）。確定・**翻訳履歴ペイン**・すべて確定・MTを挿入・MTを実行する を含む。 |

**中間生成物（`_kotonoha`）**: 実行（解析＋Pre-translation）で生成される作業ファイル（`<記事>.html`）・`uidmap`・`combined.mt-todo.json`・manifest・mt-done 等は、各プロジェクトフォルダー配下の **`_kotonoha`**（無ければ自動作成）に保存されます。行の **[詳細]** から一覧・エクスプローラー表示できます。

**動作要件**: Python 3.x。JSON/TXT は標準ライブラリのみ。**DOCX は `python-docx`、XLSX は `openpyxl`**（ユーザーサイトに導入済み。これらを使うツールは `-I` を付けずに実行）。サーバーモードのネイティブファイル選択は `tkinter`（標準同梱）。

|---|---|---|
| **XTM（元TM）** | `TM manaegment\TM\___Working\XTM\<YYYYMMDD>\` | **読み取り専用**。索引の元。書き込まない。 |

| **[9]** | UI Glossary を作成（CSV＋JSON）。→ §7b |

**一括の作業順**： **[C]（または [5] 初回のみ → [C]）→ Claude で `combined.mt-todo.json` を翻訳 → [4] → ブラウザで TEP＋確定 → XLIFF書き出し → [7] 書き戻し**。

### パスの記憶（前回値を既定表示）
- 各メニューの入力は **前回値を既定表示**。Enter で据置、変更する時だけ入力。値は `_paths.cfg`（`KEY=VALUE`）に自動保存。
- Product TMX を使わない／Project TM を Master のみにする場合は **`-`（ハイフン）** で空にできます。[8] で一覧確認と一括変更。

### 入力エラー時の挙動（再入力 / キャンセル）
- 見つからないパスや空の必須項目は `※ …が見つかりません` → **`再入力(R) / キャンセル(C)`**。**C は一つ前の入力に戻る**（最初の入力での C は中止してメニューへ）。
- 書き戻し [7] の最終確認は **Y＝実行 / N＝一つ前に戻る**。メニュー番号が無効なら `再入力(R) / 終了(Q)`。

> ⚠ `.bat` は **CRLF 改行**で保存してください（LF のみだと Windows の cmd が正しく解釈できません）。

## 4a. プロジェクト管理（作成 [C] / 一覧 [P]）

作業対象をまとめた「プロジェクト」を作成・管理し、いつでも作業を再開できます。台帳は `_projects.json`、一覧は `_projects.html`。

### [C] プロジェクト作成＋実行（ウィザード）
次の順で入力します（各ステップで現在の内容を再表示。見つからないパスは `再入力(R) / キャンセル(C=一つ前)`）。
1. **プロジェクト名**
2. **ソースの追加**：`F=ファイル追加` ／ `D=フォルダー追加（階層維持）` ／ `U=直前を取消` ／ `X=次へ`。単一／複数まぜて何件でも。
3. **メイン TM**（1つ・マッチ用）：`A=既存を指定` ／ `N=新規作成（空 TMX）`。
4. **Product TM**（任意・用語集ヒント）：`A=既存を指定` ／ `S=使わない`。
5. **サブ TM**（複数可・マッチ用）：`A=追加` ／ `N=新規作成` ／ `U=取消` ／ `X=次へ`。
6. **追加情報（任意）**：出力先フォルダー・担当者・期日・メモ。
7. 内容を一覧表示して**定義を保存**。続けて「今すぐ 解析＋Pre-translation を実行しますか？」で **Y＝実行**（成果物を台帳に登録）。

### [P] 過去のプロジェクト（ダッシュボード／コンソール操作）
`[P]` でブラウザの別タブに一覧ダッシュボードを開き、コンソールで番号を選んで操作します。
- **記事行の「開く」**：成果物 HTML を別タブで開き、作業再開。
- **定義行**：`G`＝保存した定義を解析＋Pre-translation 実行／`X`＝**元の形式で翻訳版を出力**（→ §4c）。
- `S`＝状態（作業中／レビュー中／完了）、`M`＝メモ、`E`＝期日、`D`＝削除（ファイル保持／削除を選択）、`N`＝新規作成、`R`＝再表示。
- ダッシュボード表：検索／状態フィルタ／列幅・表示・並べ替え・固定・既定復帰（ブラウザ保存）。

> ブラウザ上での操作（作成・実行・編集・各ツール）は **[D] サーバーモード**（§4b）で行えます。

## 4b. サーバーモード [D]（全機能をブラウザGUIで）

`[D]` で `projects.py serve` を起動します。**127.0.0.1 限定・ランダムトークン認証**（`X-KT-Token`）付きのローカルサーバーで、ブラウザが自動で開きます。終了はコンソールで **Ctrl+C**。

ブラウザのダッシュボード（サーバーモード）でできること：

- **＋ 新規作成**：モーダルで名前・ソース（複数）・メイン/Product/サブ TM を指定して作成（**作成のみ** / **作成して実行**）。
- **各定義行**：「**実行**」（解析＋Pre-translation・ワンクリック）／「**出力**」（元形式で翻訳版・§4c）。
- **各行の「編集」**：状態（セレクト）・メモ・期日の変更、**削除**（2段階確認）。
- **ツールバー「ツール ▾」**：
  - **MTをHTMLに反映**（単一＝HTML＋mt-done／一括＝combined）。
  - **索引キャッシュを事前作成**（University＋Product を指定。数分かかる場合あり）。
  - **TEP 結果を TM に書き戻す**：まず **dry-run** でプレビュー → 確認 → 本実行。**本実行の直前に書込先 TMX を日付きバックアップ**（`<名前>.bak_YYYYMMDD-HHMMSS.tmx`）。
  - **UI Glossary を作成**（§7b）。完了後「出力フォルダを開く」。
- **ファイル指定**は **Windows 標準の「ファイルを開く／フォルダー参照」ダイアログ**（前面表示）。tkinter が使えない環境では、サーバー内蔵のファイルブラウザに自動フォールバック。

> 重い処理（索引ビルド等）は**同期実行**です。「実行中…」の間は**タブを閉じない**でください。処理中もサーバーは他の操作を受け付けます。
>
> 静的な `_projects.html` を直接（`file://`）開いた場合は、作成・実行・編集・各ツールは使えません（「実行」はコマンドのコピーのみ）。全操作には **[D] サーバーモード**を使ってください。

## 4c. 元の形式で翻訳版を出力（JSON/DOCX/XLSX ＋ 保存先選択）

**元のファイル形式のまま翻訳版**を出力します。ダッシュボードの「**出力**」ボタン、CLI は `export`。

- **対応形式**：`.json`（Domoアプリ）・`.docx`・`.xlsx`・`.txt`（`doc_io` のレジストリ）。PDF・旧バイナリは対象外。
- **JSON の出力**は、TM の再照合ではなく**記事の訳文（Pre-translation の結果＋MT＋編集）をそのまま適用**します（100%）。`uidmap` で元 JSON の該当箇所へ書き戻し、DataSet／Magic ETL などの英語 UI 用語はそのまま残ります。
- **非 JSON（docx/xlsx/txt）**は、プロジェクト TM（メイン＋サブ）の完全一致を文単位で適用します。**TEP 書き戻し（§7a）後に実行**すると確定訳で埋まります。TM に無い文は既定で原文のまま（`--mark-missing` で `〔未訳〕`）。
- **保存先を選択**できます：出力時のダイアログで **2_For review / 3_Final / 任意のフォルダー** から選びます（既定は 2_For review）。
  - ⚠ **2_For review に元ソースと同名の成果物があると上書きになります**（元ファイルを残したいときは 3_Final か別フォルダーを選択。ダイアログにも注意書きが出ます）。
- 中間生成物は常に `_kotonoha`、最終の翻訳版は選んだ保存先に出力されます（§10）。

## 5. 使い方（コマンドライン）

Kotonoha-beta5 フォルダーで実行します。

### 索引キャッシュの事前作成（任意・初回のみ）
```powershell
python tm_index.py --tmx "…\University-….tmx" --product-tmx "…\Product-….tmx" --cache-dir "…\Kotonoha\Index"
```

### プロジェクト定義で解析＋Pre-translation を実行
```powershell
python projects.py run --id <proj-id> --cache-dir "…\Kotonoha\Index" `
  --template "TM-Match-Explorer-demo.html" --engine "tm_match_analysis.py"
```
（`idof --index <N>` で一覧の番号 → 定義 id を取得できます。）

### 元の形式で翻訳版を出力
```powershell
python projects.py export --id <proj-id> --cache-dir "…\Kotonoha\Index" [--mark-missing]
```

### サーバーモード（ブラウザGUI）
```powershell
python projects.py serve --cache-dir "…\Kotonoha\Index" `
  --template "TM-Match-Explorer-demo.html" --engine "tm_match_analysis.py"
```

### Pass 1（直接実行）
```powershell
python tm_match_analysis.py --source "…\<記事>.mdx" --tmx "…\University-….tmx" `
  --product-tmx "…\Product-….tmx" --template "TM-Match-Explorer-demo.html" `
  --out "…\TM-Match-Explorer-<記事名>.html" --cache-dir "…\Kotonoha\Index"
# フォルダー一括: --source-dir "…\記事フォルダー" --out-dir "…\Kotonoha-out" --combined-todo "…\combined.mt-todo.json"
# サブTM: --sub-tmx "…\sub1.tmx" "…\sub2.tmx"
```

| 引数 | 説明 |
|---|---|
| `--source` / `--source-dir` | 英語ソース .mdx（複数可）／フォルダー（再帰・②バッチ） |
| `--tmx` / `--sub-tmx` | 主TM（University）／サブ TM（複数・マッチ用） |
| `--product-tmx` | Product TM（UI追加マッチ＋MT用語ヒント・省略可） |
| `--out` / `--out-dir` | 単一は `--out`、バッチは `--out-dir` |

| `--combined-todo` | 全記事の `<=74%` を統合した mt-todo（③） |
| `--no-cache` / `--rebuild-cache` | キャッシュを使わない／既存を無視して再構築 |

## 6. 中間ファイルの形式

**`combined.mt-todo.json`**（②が出力／③一括翻訳の入力）
```json
{ "count": 3079,
  "articles": [ {"art":"TM-Match-Explorer-DomoStats Connector","html":"…\\….html",
                 "title":"DomoStats Connector","source":"…","segs":1703,"mt":1695} ],
  "segments": [ {"gi":0,"art":"TM-Match-Explorer-DomoStats Connector","i":2,
                 "en":"This article…","pct":32.0,
                 "glossary":[{"en":"DomoStats","ja":"DomoStats"}],
                 "tm_candidates":[{"en":"this article covers…","ja":"この記事では…","pct":"47.1"}]} ] }
```
- `gi` … 全記事横断の**グローバル通し番号**。`art`＋`i` … どの記事の何行目か。
- `glossary` … 指定 TM（Product TM）由来の用語ヒント。`tm_candidates` … **指定 TM（メイン/サブ/Product）の該当既訳（最も近い候補・類似度順に上位5件）**。MT 作成時に外部AIがこれらを参照し、TM に沿った訳にする（全プロジェクト共通）。

**`combined.mt-done.jsonl`**（Claude が作成／③一括反映の入力。1行1レコード）
```
{"gi":0,"ja":"この記事では、DomoStats コネクターについて…"}
```
- キーは `gi`（推奨）。`{"art":..,"i":..,"ja":..}` 形式も受理。単一モードは `<記事>.html.mt-done.jsonl`（`i` キー）。

## 7a. TEP 確定 → Live_TM 書き戻し（Pass 4・蓄積型）

「作業者が確定するまで書き戻さない」方針です。ブラウザで確定 → XLIFF 書き出し → `tm_writeback.py`（または [7]／サーバーモードの「ツール ▾」）で Live_TM に書き戻します。

```powershell
python tm_writeback.py --xliff "…\<記事>.xliff" --customer University --live-dir "…\Kotonoha\Live_TM"
# 複数一括: --xliff a.xliff b.xliff … / --xliff-dir "…\フォルダー"
# まず内容確認だけ: --dry-run
```

| 引数 | 説明 |
|---|---|
| `--xliff` / `--xliff-dir` | 書き出した XLIFF（複数可）／フォルダー（再帰） |
| `--customer` | `University`/`Website`/`Marketing`/`Product`/`Subtitle`。省略時は Master のみ |
| `--project-tmx` | プロジェクトTMのパスを明示指定（`--customer` の対応表を上書き） |
| `--master` / `--live-dir` | Master TMX のパス／Live_TM フォルダー |
| `--dry-run` | 変更せず、追加（new）/同一（same）件数だけ表示 |

**動作（Rev 3.00 で蓄積型に変更）**：
- 確定行（`state="final"` または note に `confirmed`）で訳文が空でないもののみ書き戻し。
- 書き込み先は **Master TMX（常に）＋プロジェクトTM（`--customer`／`--project-tmx`）**。
- **過去訳を上書き・削除しません**。同一原文に**新しい確定訳が来たら新しい版（TU）として追記**し、各 TU に更新日時（`changedate`）を付けます。**同一の訳**を再度書き戻した場合は版を増やさず日時だけ更新（重複 TU は作りません）。→ 蓄積の詳細は §7c。
- ICE 用の前後文脈（`x-previous-source-text`/`x-next-source-text`）を各 TU に付与。
- 確定が 0 件、かつ対象TMXが未作成なら**ファイルを作りません**。
- **サーバーモードの「ツール ▾ → 書き戻し」は、本実行の直前に書込先 TMX を日付きバックアップ**します。

**プロジェクトTM名（Live_TM 内・日付なし正規名）**：`Domo_Domo University-en_US-ja_JP.tmx` 等。Master は `Domo_Domo-Master.tmx`。

## 7c. 翻訳履歴（TM蓄積型）と編集画面の履歴ペイン

**目的**：過去の翻訳を失わず、いつでも参照できるようにします。

- **蓄積（書き戻し）**：§7a のとおり、同一原文に対する確定訳は**上書きせず版として TM（TU）に蓄積**されます（各版に更新日時）。
- **マッチング（Pre-translation）**：同一原文に複数版があるとき、索引は**最新版（更新日時が最大）の訳**を 100%/あいまい一致に採用します（**newest-wins**）。過去版はマッチ結果には使われません（履歴として保持されるだけ）。単一版の原文は従来どおりで、挙動は変わりません。
- **履歴ペイン（編集画面）**：行（セグメント）をクリックすると、**左下の「翻訳履歴」ペイン**にその原文の過去訳が**新しい順**（最新を強調・更新日時付き）で一覧表示されます。過去訳が無い原文は「過去訳はまだありません」。
- **レイアウト**：セグメント表＝全幅、その下に **翻訳履歴ペイン（左）｜用語ペイン（右）**。画面が狭いときは縦積み。**用語ペインは領域のみ確保**（用語集表示は今後実装）。

> 既存の Live_TM は現状「原文に 1 訳」です。**今後の書き戻しから版の蓄積が始まり**、再翻訳した原文だけ版が増えます（1 回きりの原文は 1 版のまま）。各書き戻し前の自動バックアップ（サーバーモード）とあわせ、過去の状態はファイルとしても残ります。

## 9. 制約・注意点

- 元 `.mdx` は直接上書き不可（ブラウザのセキュリティ）。編集は XLIFF 書き出し→別途反映、または **元形式で出力**（§4c・現状 .txt）。
- 静的 `file://` では作成・実行・編集・各ツールは使えません（**[D] サーバーモード**を使用）。ダウンロードは `file://` で開いた場合に機能。
- ICE は文脈プロパティ付き TMX でのみ判定可。MT は下訳（TEP 前提）。類似度は文字ベースのため XTM 実測と多少ずれます。
- 書き戻しは **XTM（元TM・読み取り専用）には一切書きません**。書き込み先は Live_TM の Master／プロジェクトTM のみ。
- **蓄積型**：同一原文の過去訳は TM に版として残り、マッチには最新版を使います（§7c）。TM が再翻訳のたびに少し大きくなります（再翻訳した原文のみ）。
- 書き戻しキーは**ソース文字列（前後空白除去）**。大文字小文字・記号差は別エントリー扱い。
- Live_TM の TMX は本ツールが管理する形式です。外部ツールで手編集した TMX を混ぜる場合は形式差に注意。
- サーバーモードは **127.0.0.1 限定＋トークン認証**（他ホスト・他サイトからはアクセス不可）。重い処理は同期（完了までタブを閉じない）。

### 10.1 起動（ハブ）とタブ・TEPウィンドウ
- **`起動_Kotonoha-ハブ.bat`** をダブルクリックで `projects.py serve` が立ち上がり、ブラウザが自動で開きます（= §4b サーバーモードの入口）。

### 10.2 プロジェクトの作成は利用者のみ／中間生成物は `_kotonoha`
- **プロジェクトを作るのは利用者だけ**です。実行して生成された記事を、ツールが勝手に別プロジェクトとして台帳へ登録することはありません（生成物はそのプロジェクトの `artifacts` として記録）。
- 実行で生成される**中間生成物**（作業ファイル `<記事>.html`・`uidmap`・`combined.mt-todo.json`・manifest・mt-done 等）は、各プロジェクトフォルダー配下の **`_kotonoha`**（無ければ自動作成）に保存されます。別プロジェクトでも、その親プロジェクトフォルダー下の `_kotonoha` で作業します。
- 行の **[詳細]** を押すと、その行の下にサブセクションが開き、**作業サマリー**（状態・ソース数・各 TM・生成記事数など）と **`_kotonoha` の中身**（ファイル一覧）が表示されます。作業ファイル(HTML)は「開いて編集」、各ファイルは「開く」でエクスプローラー表示。「フォルダーを開く」で `_kotonoha` を開きます。

### 10.3 配信は「生成ファイルそのまま」＝最新 UI は「実行」で反映
- ハブで作業ファイルを開くと、**生成された `.html` をそのまま配信**します（内容はファイルと完全一致。サーバー用トークンのみ付与）。
- そのため、**テンプレート（UI）を更新しても既存の作業ファイルには反映されません**。対象記事を **「実行」で再生成**すると、現行テンプレートで作り直されて最新 UI になります。

### 10.4 出力先の選択（§4c 参照）
- 出力時に **2_For review / 3_Final / 任意フォルダー** から保存先を選べます（既定は 2_For review）。2_For review は元ソースと同名だと上書きになる点に注意。

### 10.5 MT の任意化（反映先の制御）／MT は指定 TM を参照
> このツールに MT 翻訳エンジンは内蔵していません。MT は外部 AI（Claude 等）で `mt-todo` を翻訳→ `mt-done` を**反映**する人手フローです。ここでの「MTを実行」は**反映先の制御**です。
- **MT は指定 TM を必ず参照**：`mt-todo` の各セグメントに、用語ヒント（`glossary`＝Product TM 由来）に加えて **`tm_candidates`（指定 TM の該当既訳＝最も近い候補・類似度順に上位5件）** を同梱します（全プロジェクト共通）。外部AIはこれらを参照して TM に沿った訳を作成します。≤74% は完全一致が無い区分のため「該当既訳」は最も近い候補の利用です。
- **作成ダイアログの「MTを実行」チェック**（ブラウザに記憶し次回の作成にも引き継ぎ）：
  - **ON**：既訳のない（≤74%）セグメントの MT を**翻訳欄に反映**します（従来どおり）。
  - **OFF**：翻訳欄は**英語のまま**表示し、反映した MT の結果は**翻訳履歴ペイン**に入り、左上に日付でなく **"MT"** と表示されます。作業ファイルのツールバー **「MTを実行する」** で、履歴の MT を後から翻訳欄へまとめて反映できます。
- **翻訳欄の右クリック →「MTを挿入」**：現在の訳文はそのまま、**末尾に MT を追加**します（1 セグメントずつ）。

### 10.6 すべて確定（翻訳タブ）
- 確定列のヘッダーにある **「すべて確定」** チェックで、**現在表示中（フィルター後）**の行をまとめて確定／解除できます（訳文が空の行は対象外）。フィルターを変えると状態は同期します。

### 10.7 用語
- UI・ドキュメントで用語を統一：**Pre-translation（下訳）＝ TM訳の適用＋MT**、**「流し込み」「MT注入」は使わない**（「MTを反映」）、**TEP は作業（工程）**でファイル名ではない（生成 HTML は「**作業ファイル／編集画面**＝TEPウィンドウ」）。

### 10.8 TM タブ（TMエントリの編集）
ダッシュボードのサブタブ **プロジェクト / 用語管理 / TM** の「**TM**」。プロジェクトが参照する TM を一覧し、**書込可能TM**（`_kotonoha` 系の Main-TM 等。巨大な **XTM は読み取り専用**・サイズ上限超も編集不可）の**エントリを一覧・検索・編集（EN+JA）・削除・追加**できます。
- 上部で **TM を選択**、検索ボックスで **EN/JA 部分一致**で絞り込み。各行の **編集**（EN/JA をモーダルで修正）・**削除**、**＋ エントリ追加**。
- **書込前に日付きバックアップ**（`<TM名>.bak_YYYYMMDD-HHMMSS.tmx`）を自動作成。蓄積型（同一原文の複数版）を保持します。
- TMX を編集すると索引の指紋が変わり、次回の「実行」でキャッシュが自動再構築されます（XTM は編集対象外なので影響は限定的）。

### 10.9 Reference ボックス（参照ペインの統合・ドラッグ&ドロップ）
TEPウィンドウ翻訳タブの下部に、**翻訳履歴 / 用語集 / Concordance search**（準備中）の3ペインを内包する **Reference ボックス**（名称は非表示）。
- 各ペインの**ヘッダーをドラッグ&ドロップ**して位置を入れ替え（順序はブラウザに保存）。
- 空きスペースを作らず**自動拡張**（3ペイン時は上段2＋下段1、または画面幅に応じて縦積み）。

### 10.10 用語集ペイン（原文/訳文表示・編集）
翻訳タブの用語集ペインで、行をクリックするとその**セグメントの EN 原文・JA 訳文**を表示。原文/訳文（または本文表）で**文／句／単語を選択**すると追加フォームの EN/JA に流し込まれ、**EN/JA を編集して用語集に追加**できます。**既存用語は EN/JA をインライン編集（保存）・削除**（サーバーモード時）。用語集は全プロジェクト共通の `_terms.tsv`。

### 10.11 Concordance search（対訳用例の横断検索）
Reference ボックスの **Concordance search** ペインで、指定した TM を横断して対訳用例を検索します。
- **検索対象TM**: 既定はその記事の所属プロジェクトの TM（メイン/サブ/Product）。チェックで対象を絞り、**＋ TMを追加**（既知TM一覧から選択）・× で増減できます。各 TM に **索引:✓/未** を表示。
- **索引を作成**: チェック済みで未構築の TM について、専用の検索索引（`conc_<指紋>.pkl`）を作成します（大きい TM は初回のみ時間がかかり、以降は高速。索引キャッシュと同じ TM 管理フォルダーに保存）。
- **検索条件**: 検索語（スペース区切りで複数）＋ **フィールド（EN+JA / ENのみ / JAのみ）**＋ **AND/OR**＋ **大小区別**＋ **正規表現**。
- **結果**: **英語 / 日本語訳 / TM名 / 更新日付** の表。未構築の対象TMがあれば警告し「索引を作成」を促します。件数上限で打ち切り表示。

### 10.12 履歴タブ（操作の自動記録）／説明文の撤去・ツールチップ化
- 各ビューのタイトル下にあった**長い説明文は撤去**し、作業エリアを広く使えるようにしました。代わりに各**ボタン・チェックボックス・検索欄・タブ**にマウスオーバーで出る**ツールチップ**で使い方・内容を表示します。
- プロジェクトウィンドウのサブタブ **プロジェクト / 用語管理 / TM / 履歴** の「**履歴**」。ツールの操作（**作成・実行・出力・状態変更・削除・MTを反映・TM書き戻し・用語/TM編集・Concordance索引作成** など）を **`_history.json`** に**自動記録**し、**日付・種別・作業内容**を新しい順に一覧表示します。
- 各行の **メモ**欄にコメントを入力して「**保存**」、不要な履歴は「**削除**」できます。検索欄で作業内容・メモ・プロジェクト名を絞り込めます。`_history.json` は環境依存のため Git 管理外（自動生成）。

### 10.13 行アクションの「再開」ボタン（再解析せず既存の作業ファイルを開く）
- **一度「実行」したプロジェクト**（生成済みの作業ファイル＝`artifacts` の実体がある行）では、行のボタンが **「再開」** になります。
- **「再開」** は、再解析をせずに **既存の作業ファイル（編集画面＝TEPウィンドウ）をそのまま開きます**。前回の続きをすぐ始められます。
- ソースや TM を変えて作り直したいときは、隣の **「再解析」** を押します（＝従来の「実行」。現行テンプレートで作業ファイルを再生成します）。
- まだ一度も実行していないプロジェクトでは、従来どおり **「実行」** が表示されます。

### 10.14 UI 状態のサーバー側保存（別ブラウザ・再起動後でも復元）
- 開いていた **TEP タブの一覧とアクティブタブ**、サブタブ（プロジェクト/用語管理/TM/履歴）、**Reference ボックスの各ペインの順序・サイズ・列数・ボックス高さ**、フィルター、テーマなどの **画面の状態** を、サーバー側の **`_uistate.json`** に保存します。
- そのため、**別のブラウザや別のPCで開き直しても、ツールを再起動（ポート番号が変わっても）しても**、前回の画面状態が復元されます（従来はブラウザごとの `localStorage` 依存で、環境が変わると失われていました）。
- 仕組み: 配信ページ冒頭で前回状態を読み込み、以後の画面状態の変更を自動でサーバーへ同期します（`kotonoha-*` の設定が対象）。保存は自動で、特別な操作は不要です。
- 前回すべてのタブを閉じて終了していた場合は、起動時に空の **TM-Match-Explorer** を表示します。
- `_uistate.json` は環境依存のため **Git 管理外**（自動生成）。

### 10.15 TEP完了（確定訳をマッチ元TMへ個別書き戻し＋完了）
編集画面（TEPウィンドウ）ヘッダーの **「保存して閉じる」の右**に **「TEP完了 ✓」** ボタンがあります。翻訳作業を締めるときに押します。1クリックで、**確定済みの訳をTMへ書き戻し → プロジェクトを「完了」に → タブを閉じる** までを行います（従来の「確定→XLIFF書き出し→ツール▾→書き戻し」を集約）。
- **書き戻し対象＝確定済みセグメントのみ**。未確定が残っている場合は **警告ダイアログ**（「未 N 件は書き戻されません。続行しますか？」）が出て、**続行すると確定分だけ**書き戻します。
- **書き戻し先＝各セグメントが実際に一致してきたTM（マッチ元TM）へ個別に**。一致の無いセグメント（MT／無一致）や、マッチ元が書込不可（XTM 等の読み取り専用）・プロジェクト外のものは **メインTM** へまとめます。
- 蓄積型（既存訳を残して**新しい版として追記**・上書きしない）で、**書込前に各TMXを日付きバックアップ**します。完了すると結果（書込TM数・件数・メインTMへ回した件数）を通知し、操作は**履歴タブに「TEP完了」**として記録されます。
- あとで再度 TEP を行うときは、プロジェクトタブの **「再開」** で開き直します（§10.13）。
- **マッチ元TMへの個別ルーティングを効かせるには、対象記事を本アップデート後に一度「実行／再解析」して作業ファイルを再生成**してください（それ以前の作業ファイルには由来TM情報が無いため、確定分はすべてメインTMへ回ります）。手動書き戻し（ツール▾「TEP 結果を TM に書き戻す」）も従来どおり利用できます。

### 10.16 プロジェクトのステータス（作成済／作業中／レビュー中／完了）
プロジェクト一覧の **状態** 列は次の4値です。フィルターチップと「編集」ダイアログのセレクトで切り替え・絞り込みができます。
- **作成済**：新規作成した直後（まだ実行していない）。
- **作業中**：「実行」で作業ファイルが生成された後（翻訳・編集中）。
- **レビュー中**：任意（レビュー段階を手動で示すとき）。
- **完了**：**TEP完了**で確定訳をTMへ書き戻した後（「完了を隠す」で一覧から隠せます）。

### 10.17 オートプロパゲーション（同一原文への自動伝播）
翻訳タブのツールバーに **「自動伝播」** チェック（既定ON）があります。オンのとき、あるセグメントを **「確定」した瞬間**に、**同じ記事内で原文が完全一致（タグ含め文字単位で同一）する他のセグメント**へ同じ訳を自動で流し込みます。ボタン名・ラベル・定型文など繰り返しの多い内容で入力の手間を省けます。
- **対象＝原文が 100% 完全一致**のセグメントのみ（あいまい一致には伝播しません）。
- **伝播先は訳を入れるだけで、確定はしません**（各自でレビューして確定）。
- **伝播で訳が入ったセグメントは、Match 列に「R」**（Repetition＝繰り返し）と表示されます。そのセグメントを**手動で編集すると「R」は消えます**（通常のマッチ表示に戻ります）。「R」の状態は保存され、別ブラウザで開き直しても保持されます。
- **上書きの扱い**：伝播先が **未編集・未確定**なら訳を埋めます。すでに **異なる訳**（手動編集済み／確定済み）を持つ場合は **「N 件を上書きしますか？」と確認**し、**キャンセルすると既存訳を保持**します。
- 伝播が起きると「同一原文 N 件に訳を伝播しました」と通知します。設定（ON/OFF）はブラウザに保持されます（別ブラウザでも維持）。
- オフにすると従来どおり、確定しても他セグメントへは何も流し込みません。
