## レビュー結論（前提）
バインド=127.0.0.1ループバック、/api/* は X-KT-Token（カスタムヘッダ）必須＝CSRF緩和、subprocess は list 形式で `shell=True` 無し、CORSヘッダ無し、`/article?path=` は `os.path.abspath`＋プロジェクトルート内包＋`.html`限定、描画は概ね `esc()`。致命的な遠隔露出は無し。以下を追加ハードニング。

## 実装（projects.py）
1. **#2 `<script>` 埋め込みXSS対策**：新 `_js_embed(obj)` を追加し、`_served_prefix` の `window.__KT=` / `window.__UISTATE=` を `json.dumps` 直埋めから `_js_embed` 経由に変更。`<`→`<`・`>`→`>`・`&`→`&`・U+2028/2029 をエスケープ。プロジェクト名/ドキュメント名/TMパス/保存UI状態に `</script>` や `<!--` が混入してもスクリプトをブレイクアウトできない。
2. **#4 DNSリバインディング対策**：Handler に `_host_ok()` を追加（Host のホスト部が 127.0.0.1 / localhost / ::1 のみ許可。Host 空は許容＝curl等）。`do_GET` / `do_POST` の冒頭で `if not self._host_ok(): 403`。遠隔サイトが 127.0.0.1 へ再バインドして同一オリジン化し `/article` の翻訳内容を読む攻撃を遮断。
3. **#6 CSV/Excel 式インジェクション対策**：新 `_csv_safe(v)`（先頭が `= + - @ TAB CR` なら `'` 付与）を `export_terms` の TSV/CSV 行・XLSX セルに適用。

## 検証（実機・curl.exe）

- `GET /` に `Host: evil.example.com` → **403**（リバインディング模擬をブロック）。
