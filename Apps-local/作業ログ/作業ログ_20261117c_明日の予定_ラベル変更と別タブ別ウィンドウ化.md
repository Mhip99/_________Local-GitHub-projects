## 実装方針（案・明日詰める）
### 項目2（プロジェクト/TEPタブの別タブ・別ウィンドウ）
- 各 **プロジェクト名タブ**（および「プロジェクト」タブ見出し付近）に **「⧉別タブ」「⧈別ウィンドウ」** ボタンを追加。
  - 別タブ：`window.open('/article?id='+rowId, '_blank')`（TEP）／`window.open('/', '_blank')`（プロジェクト一覧）。
  - 別ウィンドウ：`window.open(url, '_blank', 'popup,width=1200,height=800')`。
- iframe 表示と排他にしない（別タブで開いても in-page タブは維持）。開いた側で編集→`_wip`/`_uistate` 経由でサーバー保存されるため、**状態はサーバー共有**（複数ビューの同時編集時の競合は要注意＝最後の保存優先。必要なら簡易ロック/警告を検討）。

### 項目3（セグメント/Concordance/用語集ペインの別タブ・別ウィンドウ）
- **Concordance・用語集**：既に server API 駆動（`/api/concordance*`・`/api/terms*`）。**単一ペインを描画するスタンドアロン・ルート**を新設するのが本筋：
  - 案A（推奨）：`projects.py` に `/pane?type=concordance|glossary|segments&id=<rowId>` を追加し、ペイン単体のHTML（既存CSS/JSを流用）を配信＋`window.__KT` 注入。各ペインの「⧉別タブ/別ウィンドウ」ボタンから `window.open`。
  - 案B（簡易）：既存の記事HTMLを新ウィンドウで開き、該当ペインだけ表示に切替えるクエリ（`#pane=concordance` 等）で初期フォーカス。実装軽いが「ペイン単体」にはならない。
- **翻訳（セグメント）ペイン**：SEG データが記事HTMLに内包されるため単体化はやや重い。案A なら `/pane?type=segments&id=` でそのSEGを読み、編集は `/api/save-edits` 共有。→ **項目2（記事まるごと別タブ）で代替できる部分**もあるため、まず Concordance/用語集の単体ポップアウトから着手し、セグメント単体は必要性を再確認。
- **決定事項**：ペイン単体ルート（案A）を作るか、記事まるごと別タブ（案B 寄り）で妥協するか。D&D並べ替え・`_uistate` 復元との整合も確認。
