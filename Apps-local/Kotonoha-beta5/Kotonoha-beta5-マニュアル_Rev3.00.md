## 4. 使い方（バッチ / ランチャー）

`TM-Match-Explorer.bat` をダブルクリック。

| 選択 | 内容 |
|---|---|
| **[C]** | **プロジェクト作成＋実行**（単一記事・フォルダー）。名前・ソース・TM を登録し、そのまま解析＋Pre-translation まで実行できます。→ §4a |
| **[P]** | **過去のプロジェクト**（一覧ダッシュボードを別タブ表示・作業再開・状態管理・保存した定義の実行 G・元形式で出力 X）。→ §4a |
| **[D]** | **ダッシュボードを開く（サーバーモード）**：ローカルサーバーを起動し、ブラウザから作成・実行・出力・編集・各ツールを操作。→ §4b |
| **[3]** | MTを反映（単一）。 |
| **[4]** | MT一括反映（③・combined）。 |
| **[5]** | 索引キャッシュを事前作成（初回のみ・数分）。 |
| **[6]** | テンプレートをプレビュー。 |
| **[7]** | TEP確定行を TM へ書き戻し（確定行のみ・dry-run確認あり・**蓄積型**）。→ §7a |
| **[8]** | パス設定を表示 / 変更。 |
| **[9]** | UI Glossary を作成（CSV＋JSON）。→ §7b |

> 旧 **[1]/[2]（解析＋Pre-translation）は [C]/[P] に一本化**しました（2026-10-08）。単一記事はソースにファイルを1つ、フォルダー一括はフォルダーを追加して実行します。

**一括の作業順**： **[C]（または [5] 初回のみ → [C]）→ Claude で `combined.mt-todo.json` を翻訳 → [4] → ブラウザで TEP＋確定 → XLIFF書き出し → [7] 書き戻し**。

### パスの記憶（前回値を既定表示）
- 各メニューの入力は **前回値を既定表示**。Enter で据置、変更する時だけ入力。値は `_paths.cfg`（`KEY=VALUE`）に自動保存。
- Product TMX を使わない／Project TM を Master のみにする場合は **`-`（ハイフン）** で空にできます。[8] で一覧確認と一括変更。

### 入力エラー時の挙動（再入力 / キャンセル）
- 見つからないパスや空の必須項目は `※ …が見つかりません` → **`再入力(R) / キャンセル(C)`**。**C は一つ前の入力に戻る**（最初の入力での C は中止してメニューへ）。
- 書き戻し [7] の最終確認は **Y＝実行 / N＝一つ前に戻る**。メニュー番号が無効なら `再入力(R) / 終了(Q)`。

> ⚠ `.bat` は **CRLF 改行**で保存してください（LF のみだと Windows の cmd が正しく解釈できません）。

## 4a. プロジェクト管理（作成 [C] / 一覧 [P]）

作業対象をまとめた「プロジェクト」を作成・管理し、いつでも作業を再開できます。台帳は `_projects.json`、一覧は `_projects.html`。

### [C] プロジェクト作成＋実行（ウィザード）
次の順で入力します（各ステップで現在の内容を再表示。見つからないパスは `再入力(R) / キャンセル(C=一つ前)`）。
1. **プロジェクト名**
2. **ソースの追加**：`F=ファイル追加` ／ `D=フォルダー追加（階層維持）` ／ `U=直前を取消` ／ `X=次へ`。単一／複数まぜて何件でも。
3. **メイン TM**（1つ・マッチ用）：`A=既存を指定` ／ `N=新規作成（空 TMX）`。
4. **Product TM**（任意・用語集ヒント）：`A=既存を指定` ／ `S=使わない`。
5. **サブ TM**（複数可・マッチ用）：`A=追加` ／ `N=新規作成` ／ `U=取消` ／ `X=次へ`。
6. **追加情報（任意）**：出力先フォルダー・担当者・期日・メモ。
7. 内容を一覧表示して**定義を保存**。続けて「今すぐ 解析＋Pre-translation を実行しますか？」で **Y＝実行**（成果物を台帳に登録）。

### [P] 過去のプロジェクト（ダッシュボード／コンソール操作）
`[P]` でブラウザの別タブに一覧ダッシュボードを開き、コンソールで番号を選んで操作します。
- **記事行の「開く」**：成果物 HTML を別タブで開き、作業再開。
- **定義行**：`G`＝保存した定義を解析＋Pre-translation 実行／`X`＝**元の形式で翻訳版を出力**（→ §4c）。
- `S`＝状態（作業中／レビュー中／完了）、`M`＝メモ、`E`＝期日、`D`＝削除（ファイル保持／削除を選択）、`N`＝新規作成、`R`＝再表示。
- ダッシュボード表：検索／状態フィルタ／列幅・表示・並べ替え・固定・既定復帰（ブラウザ保存）。

> ブラウザ上での操作（作成・実行・編集・各ツール）は **[D] サーバーモード**（§4b）で行えます。

## 4b. サーバーモード [D]（全機能をブラウザGUIで）

`[D]` で `projects.py serve` を起動します。**127.0.0.1 限定・ランダムトークン認証**（`X-KT-Token`）付きのローカルサーバーで、ブラウザが自動で開きます。終了はコンソールで **Ctrl+C**。

ブラウザのダッシュボード（サーバーモード）でできること：

- **＋ 新規作成**：モーダルで名前・ソース（複数）・メイン/Product/サブ TM を指定して作成（**作成のみ** / **作成して実行**）。
- **各定義行**：「**実行**」（解析＋Pre-translation・ワンクリック）／「**出力**」（元形式で翻訳版・§4c）。
- **各行の「編集」**：状態（セレクト）・メモ・期日の変更、**削除**（2段階確認）。
- **ツールバー「ツール ▾」**：
  - **MTをHTMLに反映**（単一＝HTML＋mt-done／一括＝combined）。
  - **索引キャッシュを事前作成**（University＋Product を指定。数分かかる場合あり）。
  - **TEP 結果を TM に書き戻す**：まず **dry-run** でプレビュー → 確認 → 本実行。**本実行の直前に書込先 TMX を日付きバックアップ**（`<名前>.bak_YYYYMMDD-HHMMSS.tmx`）。
  - **UI Glossary を作成**（§7b）。完了後「出力フォルダを開く」。
- **ファイル指定**は **Windows 標準の「ファイルを開く／フォルダー参照」ダイアログ**（前面表示）。tkinter が使えない環境では、サーバー内蔵のファイルブラウザに自動フォールバック。

> 重い処理（索引ビルド等）は**同期実行**です。「実行中…」の間は**タブを閉じない**でください。処理中もサーバーは他の操作を受け付けます。
>
> 静的な `_projects.html` を直接（`file://`）開いた場合は、作成・実行・編集・各ツールは使えません（「実行」はコマンドのコピーのみ）。全操作には **[D] サーバーモード**を使ってください。

## 4c. 元の形式で翻訳版を出力（多フォーマット往復）

TM（プロジェクトのメイン＋サブ TM）を文単位で適用し、**元のファイル形式のまま翻訳版**を出力します。`[P]→X` または ダッシュボードの「出力」ボタン、CLI は `export`／`doc_export.py`。

- **現状の対応形式は `.txt`**（行＝ユニット、空行・インデント・改行コードを保持。1行内の複数文も TM で再構成）。docx/xlsx/pptx は今後 `doc_io.py` のレジストリに追加予定（PDF・旧バイナリは後回し）。
- 出力は プロジェクトの出力先フォルダー配下 `translated\<元の相対パス>` に、**元の拡張子**で生成。
- 訳の出所は**プロジェクト TM の完全一致**。**TEP 書き戻し（§7a）後に実行**すると、確定訳で全文が埋まります。TM に無い文は既定で原文のまま（オプションで `〔未訳〕` を付与）。

## 5. 使い方（コマンドライン）

Kotonoha-beta3 フォルダーで実行します。

### 索引キャッシュの事前作成（任意・初回のみ）
```powershell
python tm_index.py --tmx "…\University-….tmx" --product-tmx "…\Product-….tmx" --cache-dir "…\Kotonoha\Index"
```

### プロジェクト定義で解析＋Pre-translation を実行
```powershell
python projects.py run --id <proj-id> --cache-dir "…\Kotonoha\Index" `
  --template "TM-Match-Explorer-demo.html" --engine "tm_match_analysis.py"
```
（`idof --index <N>` で一覧の番号 → 定義 id を取得できます。）

### 元の形式で翻訳版を出力
```powershell
python projects.py export --id <proj-id> --cache-dir "…\Kotonoha\Index" [--mark-missing]
```

### サーバーモード（ブラウザGUI）
```powershell
python projects.py serve --cache-dir "…\Kotonoha\Index" `
  --template "TM-Match-Explorer-demo.html" --engine "tm_match_analysis.py"
```

### Pass 1（直接実行）
```powershell
python tm_match_analysis.py --source "…\<記事>.mdx" --tmx "…\University-….tmx" `
  --product-tmx "…\Product-….tmx" --template "TM-Match-Explorer-demo.html" `
  --out "…\TM-Match-Explorer-<記事名>.html" --cache-dir "…\Kotonoha\Index"
# フォルダー一括: --source-dir "…\記事フォルダー" --out-dir "…\Kotonoha-out" --combined-todo "…\combined.mt-todo.json"
# サブTM: --sub-tmx "…\sub1.tmx" "…\sub2.tmx"
```

| 引数 | 説明 |
|---|---|
| `--source` / `--source-dir` | 英語ソース .mdx（複数可）／フォルダー（再帰・②バッチ） |
| `--tmx` / `--sub-tmx` | 主TM（University）／サブ TM（複数・マッチ用） |
| `--product-tmx` | Product TM（UI追加マッチ＋MT用語ヒント・省略可） |
| `--out` / `--out-dir` | 単一は `--out`、バッチは `--out-dir` |
| `--cache-dir` | 索引キャッシュ（既定＝TM management の Index） |
| `--combined-todo` | 全記事の `<=74%` を統合した mt-todo（③） |
| `--no-cache` / `--rebuild-cache` | キャッシュを使わない／既存を無視して再構築 |

### Pass 3 — MTを反映
```powershell
python inject_mt.py --html "…\<記事>.html" --mt "…\<記事>.html.mt-done.jsonl"
# 一括(③): --combined-todo "…\combined.mt-todo.json" --combined-mt "…\combined.mt-done.jsonl"
```

## 7. マッチ区分・UI・XLIFF 出力

マッチ区分は **beta1 と同一**（ICE / 100% / 95-99 / 85-94 / 75-84% はTM訳の適用、`<=74%` は MT）。ブラウザ UI（サマリー・フィルター・編集モード・localStorage 自動保存・XLIFF 1.2 書き出し）も基本は beta1 と同じ。

**「確定（Confirm）」**（beta2〜）：各行の確定チェックボックス、「表示中を一括確定」、「確定済みのみ」フィルター。確定は `localStorage` に自動保存。確定行を**編集すると確定は自動解除**。XLIFF 書き出し時、確定行は `state="final"` ＋ `<note>` に `| confirmed`。**この確定行だけ**が §7a の書き戻し対象です。

**翻訳履歴ペイン（Rev 3.00〜）**：編集画面の下部に、表＝全幅、その下に **履歴ペイン（左）｜用語ペイン（右）** を配置。行をクリックすると、その原文の**過去訳＋更新日時**が新しい順に履歴ペインへ表示されます（→ §7c）。用語ペインは領域のみ（用語集表示は今後）。

## 7a. TEP 確定 → Live_TM 書き戻し（Pass 4・蓄積型）

「作業者が確定するまで書き戻さない」方針です。ブラウザで確定 → XLIFF 書き出し → `tm_writeback.py`（または [7]／サーバーモードの「ツール ▾」）で Live_TM に書き戻します。

```powershell
python tm_writeback.py --xliff "…\<記事>.xliff" --customer University --live-dir "…\Kotonoha\Live_TM"
# 複数一括: --xliff a.xliff b.xliff … / --xliff-dir "…\フォルダー"
# まず内容確認だけ: --dry-run
```

| 引数 | 説明 |
|---|---|
| `--xliff` / `--xliff-dir` | 書き出した XLIFF（複数可）／フォルダー（再帰） |
| `--customer` | `University`/`Website`/`Marketing`/`Product`/`Subtitle`。省略時は Master のみ |
| `--project-tmx` | プロジェクトTMのパスを明示指定（`--customer` の対応表を上書き） |
| `--master` / `--live-dir` | Master TMX のパス／Live_TM フォルダー |
| `--dry-run` | 変更せず、追加（new）/同一（same）件数だけ表示 |

**動作（Rev 3.00 で蓄積型に変更）**：
- 確定行（`state="final"` または note に `confirmed`）で訳文が空でないもののみ書き戻し。
- 書き込み先は **Master TMX（常に）＋プロジェクトTM（`--customer`／`--project-tmx`）**。
- **過去訳を上書き・削除しません**。同一原文に**新しい確定訳が来たら新しい版（TU）として追記**し、各 TU に更新日時（`changedate`）を付けます。**同一の訳**を再度書き戻した場合は版を増やさず日時だけ更新（重複 TU は作りません）。→ 蓄積の詳細は §7c。
- ICE 用の前後文脈（`x-previous-source-text`/`x-next-source-text`）を各 TU に付与。
- 確定が 0 件、かつ対象TMXが未作成なら**ファイルを作りません**。
- **サーバーモードの「ツール ▾ → 書き戻し」は、本実行の直前に書込先 TMX を日付きバックアップ**します。

**プロジェクトTM名（Live_TM 内・日付なし正規名）**：`Domo_Domo University-en_US-ja_JP.tmx` 等。Master は `Domo_Domo-Master.tmx`。

## 7b. UI Glossary 作成（ui_glossary.py・メニュー[9]）

**作業内容から UI 用語（UI 要素・コマンド・メッセージ）を抽出**し、EN→JA の用語集を **CSV＋JSON** で出力します。

```powershell
python ui_glossary.py --source "…\<記事>.mdx" --html "…\<記事>.html" `
  --xliff "…\<記事>.xliff" [--confirmed-only] `
  --product-tmx "…\Product-….tmx" --tmx "…\University-….tmx" --cache-dir "…\Index" `
  --out "…\UI-Glossary"
```

- `--source` / `--html` / `--xliff` の **1つ以上**が必要（併用可）。
- **抽出対象**：ソース `.mdx`（`**太字**`／`` `コード` ``／`A > B` メニューパス）、HTML/XLIFF の短い UI ラベル・メッセージ。
- **JA の補完（優先順）**：① 確定/セグメント訳 → ② Product/University TM の完全一致 → ③ コマンド・製品名は原語のまま → ④ 空欄。
- **出力列**（CSV, `EN, JA, Type, JA_source, Count`）。CSV は UTF-8 BOM付き（Excel 可）。
- `--max-words`（既定 6）で UI 用語とみなす最大語数を調整。

## 7c. 翻訳履歴（TM蓄積型）と編集画面の履歴ペイン

**目的**：過去の翻訳を失わず、いつでも参照できるようにします。

- **蓄積（書き戻し）**：§7a のとおり、同一原文に対する確定訳は**上書きせず版として TM（TU）に蓄積**されます（各版に更新日時）。
- **マッチング（Pre-translation）**：同一原文に複数版があるとき、索引は**最新版（更新日時が最大）の訳**を 100%/あいまい一致に採用します（**newest-wins**）。過去版はマッチ結果には使われません（履歴として保持されるだけ）。単一版の原文は従来どおりで、挙動は変わりません。
- **履歴ペイン（編集画面）**：行（セグメント）をクリックすると、**左下の「翻訳履歴」ペイン**にその原文の過去訳が**新しい順**（最新を強調・更新日時付き）で一覧表示されます。過去訳が無い原文は「過去訳はまだありません」。
- **レイアウト**：セグメント表＝全幅、その下に **翻訳履歴ペイン（左）｜用語ペイン（右）**。画面が狭いときは縦積み。**用語ペインは領域のみ確保**（用語集表示は今後実装）。

> 既存の Live_TM は現状「原文に 1 訳」です。**今後の書き戻しから版の蓄積が始まり**、再翻訳した原文だけ版が増えます（1 回きりの原文は 1 版のまま）。各書き戻し前の自動バックアップ（サーバーモード）とあわせ、過去の状態はファイルとしても残ります。

## 9. 制約・注意点

- 元 `.mdx` は直接上書き不可（ブラウザのセキュリティ）。編集は XLIFF 書き出し→別途反映、または **元形式で出力**（§4c・現状 .txt）。
- 静的 `file://` では作成・実行・編集・各ツールは使えません（**[D] サーバーモード**を使用）。ダウンロードは `file://` で開いた場合に機能。
- ICE は文脈プロパティ付き TMX でのみ判定可。MT は下訳（TEP 前提）。類似度は文字ベースのため XTM 実測と多少ずれます。
- 書き戻しは **XTM（元TM・読み取り専用）には一切書きません**。書き込み先は Live_TM の Master／プロジェクトTM のみ。
- **蓄積型**：同一原文の過去訳は TM に版として残り、マッチには最新版を使います（§7c）。TM が再翻訳のたびに少し大きくなります（再翻訳した原文のみ）。
- 書き戻しキーは**ソース文字列（前後空白除去）**。大文字小文字・記号差は別エントリー扱い。
- Live_TM の TMX は本ツールが管理する形式です。外部ツールで手編集した TMX を混ぜる場合は形式差に注意。
- サーバーモードは **127.0.0.1 限定＋トークン認証**（他ホスト・他サイトからはアクセス不可）。重い処理は同期（完了までタブを閉じない）。
